# 15 图结构

## 学习目标
1. 理解为什么要用图结构来组织复杂流程
2. 掌握 LangGraph 中节点、边、状态的配合方式
3. 学会构建顺序执行、条件分支和循环三种常见图结构
4. 能够看懂图结构的执行路径，并根据需求修改流程
5. 为后续多智能体、工作流和复杂 Agent 打下基础

## 1. 为什么需要图结构

在前面的课程中，我们已经学过链（Chain）：

```
输入 -> Prompt -> 模型 -> 输出
```

这种结构很适合**线性流程**，也就是每一步都按固定顺序往下走。

但是在真实应用中，流程往往没有这么简单。例如：

- 如果用户的问题不完整，要先追问再继续
- 如果模型判断需要调用工具，要进入工具节点
- 如果工具返回的信息还不够，要再循环一次
- 如果满足某个条件，要走 A 路线，否则走 B 路线

这时，单纯的链就不够用了。我们需要一种更灵活的结构，让流程能够：

- **分支**：根据条件走不同路线
- **回路**：重复执行直到满足条件
- **汇合**：多条路径最后回到同一个结果

这就是**图结构（Graph）**的价值。

## 2. 图结构的核心组成

在 LangGraph 中，一个图通常由三部分组成：

### 2.1 State（状态）
状态可以理解为‘流程执行时共享的一份数据’。

例如一个状态可能长这样：

```python
{'value': 3, 'result': '通过', 'step': 2}
```

图中的每个节点都可以读取这份状态，也可以返回对状态的更新。

### 2.2 Node（节点）
节点就是图中的一个处理步骤。

你可以把节点理解成‘流水线上的一个工位’。每个工位做一件事，例如：

- 给数字加 1
- 判断成绩是否及格
- 调用大模型生成回复
- 调用搜索工具获取资料

### 2.3 Edge（边）
边表示‘从哪个节点走到哪个节点’。

边决定了执行顺序。常见有两种：

- **普通边**：固定走向下一个节点
- **条件边**：根据状态判断下一步走哪条路

可以把图结构想象成一张地铁路线图：

- 状态 = 你当前身上的信息
- 节点 = 你经过的站点
- 边 = 站点之间的路线

## 3. 第一个图：顺序执行

先从最简单的情况开始：

```
START -> 加一 -> 乘二 -> END
```

也就是说：

1. 初始值是 `value=3`
2. 第一个节点先把它加 1，变成 4
3. 第二个节点再把它乘 2，变成 8
4. 最后输出结果

```python
from typing_extensions import TypedDict
from langgraph.graph import StateGraph, START, END

# 1. 定义状态结构
class NumberState(TypedDict):
    value: int

# 2. 定义节点函数
def add_one(state: NumberState):
    print(f'进入 add_one 前，value = {state["value"]}')
    return {'value': state['value'] + 1}

def multiply_two(state: NumberState):
    print(f'进入 multiply_two 前，value = {state["value"]}')
    return {'value': state['value'] * 2}

# 3. 创建图
builder = StateGraph(NumberState)

# 4. 添加节点
builder.add_node('add_one', add_one)
builder.add_node('multiply_two', multiply_two)

# 5. 添加边
builder.add_edge(START, 'add_one')
builder.add_edge('add_one', 'multiply_two')
builder.add_edge('multiply_two', END)

# 6. 编译图
graph = builder.compile()

# 7. 执行图
result = graph.invoke({'value': 3})
print('最终结果：', result)
```

### 代码解释

这段代码虽然不长，但非常关键，值得逐行理解。

#### 第 1 步：定义状态
`NumberState` 规定了图里共享的数据结构，这里只有一个字段：`value`。

也就是说，整张图传来传去的核心数据就是一个整数。

#### 第 2 步：定义节点函数
`add_one(state)` 和 `multiply_two(state)` 都接收当前状态。

例如当状态是：

```python
{'value': 3}
```

那么 `add_one` 返回：

```python
{'value': 4}
```

节点函数**不需要返回完整状态**，只要返回要更新的字段即可。LangGraph 会把更新结果合并回状态中。

#### 第 3 步：创建图
`StateGraph(NumberState)` 表示：我们要创建一张图，并且这张图中的状态结构由 `NumberState` 定义。

#### 第 4 步：添加节点
`builder.add_node('add_one', add_one)` 的意思是：

- 节点名字叫 `add_one`
- 这个节点真正执行的函数是 Python 函数 `add_one`

节点名字更像是图里的‘标签’，函数才是‘真正干活的人’。

#### 第 5 步：添加边
这三行定义了执行路径：

- 从 `START` 进入 `add_one`
- 从 `add_one` 进入 `multiply_two`
- 从 `multiply_two` 进入 `END`

因此执行顺序是固定的，没有分支，也没有循环。

#### 第 6 步：编译图
`compile()` 会把‘图的定义’变成一个真正可运行的对象。

你可以把它理解为：前面是在画流程图，这一步是把流程图变成程序。

#### 第 7 步：运行图
`graph.invoke({'value': 3})` 表示用初始状态 `{'value': 3}` 启动整张图。

执行过程是：

1. `value=3` 进入 `add_one`
2. 更新为 `value=4`
3. `value=4` 进入 `multiply_two`
4. 更新为 `value=8`
5. 图结束，输出 `{'value': 8}`

## 4. 查看图结构

除了运行图，我们还可以把图的结构打印出来，帮助自己检查流程是否连对了。

```python
print('节点：')
print(graph.get_graph().nodes)

print('\n边：')
print(graph.get_graph().edges)

print('\nMermaid 图：')
print(graph.get_graph().draw_mermaid())
```

### 代码解释

这一段代码的重点不在‘计算’，而在‘观察图’。

#### `graph.get_graph().nodes`
它会返回当前图中有哪些节点。你可以把它理解为‘流程图里有哪些方框’。

#### `graph.get_graph().edges`
它会返回节点之间的连接关系，也就是‘箭头从哪里指向哪里’。

#### `draw_mermaid()`
它会生成 Mermaid 格式的流程图文本。

Mermaid 是一种用文本描述流程图的语法，例如：

```
START --> add_one --> multiply_two --> END
```

你可以把输出复制到支持 Mermaid 的工具中查看图形化效果。

这在图结构变复杂之后尤其有用，因为：

- 可以快速确认自己有没有连错边
- 可以帮助团队成员理解流程
- 可以作为调试流程的一部分

## 5. 条件分支图

前面的图是固定顺序执行。现在我们来做一个更像真实业务的例子：**根据分数决定是否通过**。

流程如下：

```
START -> 判断分数 -> 合格 / 不合格 -> END
```

如果分数大于等于 60，就走‘通过’节点；否则走‘补考’节点。

这就是典型的**条件分支**。

```python
from typing_extensions import TypedDict
from langgraph.graph import StateGraph, START, END

class ScoreState(TypedDict):
    score: int
    result: str

def check_score(state: ScoreState):
    print(f'当前分数：{state["score"]}')
    return {}

def pass_node(state: ScoreState):
    return {'result': '成绩合格，顺利通过'}

def fail_node(state: ScoreState):
    return {'result': '成绩不合格，需要补考'}

def route_by_score(state: ScoreState):
    if state['score'] >= 60:
        return 'pass_node'
    return 'fail_node'

builder = StateGraph(ScoreState)
builder.add_node('check_score', check_score)
builder.add_node('pass_node', pass_node)
builder.add_node('fail_node', fail_node)

builder.add_edge(START, 'check_score')
builder.add_conditional_edges(
    'check_score',
    route_by_score,
    {
        'pass_node': 'pass_node',
        'fail_node': 'fail_node'
    }
)
builder.add_edge('pass_node', END)
builder.add_edge('fail_node', END)

score_graph = builder.compile()

print('分数 85 的结果：')
print(score_graph.invoke({'score': 85, 'result': ''}))

print('\n分数 45 的结果：')
print(score_graph.invoke({'score': 45, 'result': ''}))
```

### 代码解释

这个例子第一次出现了**条件边**，所以需要重点掌握。

#### 状态结构
这里的状态包含两个字段：

- `score`：输入分数
- `result`：最终判断结果

也就是说，这张图的目标是：根据 `score` 计算出 `result`。

#### `check_score` 节点
这个节点本身没有修改状态，只是把当前分数打印出来。

它返回 `{}`，表示‘这个节点不更新任何字段’。

这说明一个节点不一定非要做数据修改，它也可以只承担‘中转’或‘判断前准备’的作用。

#### `pass_node` 和 `fail_node`
这两个节点分别代表两条不同路径的处理结果：

- 如果通过，更新 `result='成绩合格，顺利通过'`
- 如果不通过，更新 `result='成绩不合格，需要补考'`

这两个节点就像流程图里分叉后的两条支路。

#### `route_by_score`：路由函数
这是本例最核心的部分。

它不是真正的业务节点，而是一个‘路线选择器’。它根据当前状态判断：

- `score >= 60` 返回 `'pass_node'`
- 否则返回 `'fail_node'`

返回值必须和后面条件边映射表中的 key 对应上。

#### `add_conditional_edges(...)`
这段代码的意思是：

从 `check_score` 节点出来后，不是固定走下一步，而是调用 `route_by_score(state)`。

如果返回 `'pass_node'`，就走到 `pass_node`；如果返回 `'fail_node'`，就走到 `fail_node`。

你可以把它理解成：

- 普通边 = 固定导航
- 条件边 = 智能导航

#### 最终执行效果
当输入 `score=85` 时，流程是：

```
START -> check_score -> pass_node -> END
```

当输入 `score=45` 时，流程是：

```
START -> check_score -> fail_node -> END
```

这就是图结构中‘根据条件走不同路线’的最基本模式。

## 6. 循环图

除了分支，图结构还有一个非常重要的能力：**循环**。

在很多智能体任务中，我们都需要重复执行某些步骤，比如：

- 检索不到足够信息就继续搜索
- 模型输出格式不对就重新生成
- 工具调用结果不完整就继续补充

下面我们用一个简单例子说明循环：

让 `count` 从 0 开始，每次加 1，直到加到 3 为止。

流程如下：

```
START -> increment -> 判断是否结束
                 ↘ 未结束，回到 increment
                 ↘ 已结束，进入 END
```

```python
from typing_extensions import TypedDict
from langgraph.graph import StateGraph, START, END

class LoopState(TypedDict):
    count: int

def increment(state: LoopState):
    new_count = state['count'] + 1
    print(f'当前 count 从 {state["count"]} 变成 {new_count}')
    return {'count': new_count}

def should_continue(state: LoopState):
    if state['count'] < 3:
        return 'continue'
    return 'stop'

builder = StateGraph(LoopState)
builder.add_node('increment', increment)

builder.add_edge(START, 'increment')
builder.add_conditional_edges(
    'increment',
    should_continue,
    {
        'continue': 'increment',
        'stop': END
    }
)

loop_graph = builder.compile()
result = loop_graph.invoke({'count': 0})
print('最终状态：', result)
```

### 代码解释

这个例子看起来简单，但它已经具备了很多 Agent 工作流的核心思想。

#### `increment` 节点
它的职责非常明确：每次把 `count` 加 1。

例如：

- 输入 `count=0`，输出 `count=1`
- 输入 `count=1`，输出 `count=2`
- 输入 `count=2`，输出 `count=3`

#### `should_continue` 路由函数
它负责判断是继续循环，还是结束流程。

规则很简单：

- 如果 `count < 3`，返回 `'continue'`
- 否则返回 `'stop'`

#### 条件边的映射
这里最关键的一点是：

- `'continue'` 映射到 `'increment'`
- `'stop'` 映射到 `END`

这就意味着：

- 只要还没达到条件，就重新回到同一个节点
- 达到条件后，就退出图

这就是循环结构的本质。

#### 执行过程
如果初始状态是 `{'count': 0}`，执行路径如下：

1. 进入 `increment`，变成 `count=1`
2. 判断 `1 < 3`，继续
3. 再次进入 `increment`，变成 `count=2`
4. 判断 `2 < 3`，继续
5. 再次进入 `increment`，变成 `count=3`
6. 判断 `3 < 3` 不成立，停止
7. 进入 `END`

也就是说，图结构中的循环并不是 `for` 或 `while` 语法写出来的，而是通过‘节点 + 条件边回跳’实现的。

这也是 LangGraph 很强大的地方：它把‘流程控制’变成了图本身的一部分。

## 7. 图结构和普通 Python 流程控制有什么区别

你可能会问：

‘这些分支和循环，我直接用 `if`、`while` 不也能写吗？’

当然可以。但图结构有几个明显优势：

| 对比点 | 普通 Python 代码 | 图结构 |
| --- | --- | --- |
| 流程表达方式 | 写在代码逻辑里 | 显式画成节点和边 |
| 可视化能力 | 弱 | 强 |
| 分支/回路可读性 | 复杂时容易乱 | 更直观 |
| 与 Agent / 工作流结合 | 需要手动组织 | 天然适合 |
| 状态传递 | 自己管理变量 | 统一用 State 管理 |

最核心的一点是：

**图结构不是为了替代 Python，而是为了让复杂流程更容易设计、理解、调试和扩展。**

## 8. 一个更贴近 Agent 的理解方式

如果把图结构放到 AI Agent 场景中，可以这样理解：

- 一个节点可以是‘调用大模型’
- 一个节点可以是‘调用工具’
- 一个节点可以是‘检查结果是否满足要求’
- 条件边可以决定‘是继续调用工具，还是给用户最终答案’

也就是说，后面你学到的复杂 Agent，本质上大多都可以拆成：

```
理解问题 -> 决策 -> 调工具 -> 检查结果 -> 继续/结束
```

而图结构正是把这条路线显式表达出来的最好方式。

## 9. 本节小结

本节课你需要记住三个最重要的结论：

1. **State 是共享数据**：节点之间通过状态传递信息
2. **Node 是处理步骤**：每个节点负责完成一个明确任务
3. **Edge 决定执行路径**：普通边用于顺序执行，条件边用于分支和循环

掌握了这三点，你就已经理解了图结构的核心。后面无论是多轮工作流、工具调用循环，还是多智能体协作，本质上都只是图结构的进一步扩展。
