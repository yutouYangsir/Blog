# 19 循环与记忆

## 学习目标
1. 理解LangGraph中循环和持久化记忆的实现方式
2. 掌握MemorySaver的使用，实现对话状态持久化
3. 能够构建支持多轮交互的智能体流程

## 1. 为什么需要循环和记忆

在之前的课程中，我们构建的图流程都是**单次执行**的：

```
START -> node_a -> node_b -> END
```

这种流程跑一次就结束了。但真实场景中，很多需求需要**多次循环**和**记忆状态**：

- **聊天机器人**：需要记住之前说过的话，才能进行多轮对话
- **任务分解**：可能需要反复调用工具，直到任务完成
- **信息收集**：需要逐步收集用户的信息，直到完整
- **多用户系统**：每个用户的对话历史需要独立保存

简单来说：

- **循环**：让流程可以重复执行某些节点
- **记忆**：让状态可以在多次执行之间保持

## 2. 循环的实现方式

在LangGraph中，循环主要通过**条件边**来实现。关键思路是：

1. 执行某个节点
2. 判断是否需要继续循环
3. 如果需要，回到之前的节点重新执行
4. 如果不需要，走向结束

流程图如下：

```
START -> work_node -> 判断节点
                        |
              ┌─────────┴─────────┐
              ▼                   ▼
           继续循环             结束
              |                   |
              └───────► work_node ◄──┘
```

用条件边实现就是：`判断节点` 根据状态返回 `'loop'` 或 `'end'`，然后：

- `'loop'` → 回到 `work_node`
- `'end'` → 走到 `END`

## 3. 第一个例子：简单的计数器循环

我们用一个计数器来演示循环的基本实现。

流程目标：
- 从0开始计数
- 每次加1
- 当计数达到5时停止
- 每次循环都打印当前计数值

```python
from typing_extensions import TypedDict
from langgraph.graph import StateGraph, START, END

class CounterState(TypedDict):
    count: int

def increment_node(state: CounterState):
    new_count = state['count'] + 1
    print(f'当前计数：{new_count}')
    return {'count': new_count}

def should_continue(state: CounterState):
    if state['count'] < 5:
        return 'loop'
    return 'end'

builder = StateGraph(CounterState)
builder.add_node('increment', increment_node)

builder.add_edge(START, 'increment')
builder.add_conditional_edges(
    'increment',
    should_continue,
    {
        'loop': 'increment',
        'end': END
    }
)

graph = builder.compile()
result = graph.invoke({'count': 0})
print(result)
```

### 代码解释

1. **State 定义**：`CounterState` 只包含一个字段 `count`，用于存储当前计数值。

2. **increment_node**：每次执行时，从状态中取出 `count`，加1后放回状态。同时打印当前计数值。

3. **should_continue**：路由函数，判断是否继续循环。如果 `count < 5` 返回 `'loop'`，否则返回 `'end'`。

4. **条件边设置**：
   - 来源节点是 `'increment'`
   - 路由函数是 `should_continue`
   - 如果返回 `'loop'`，就回到 `'increment'` 节点（形成循环）
   - 如果返回 `'end'`，就走到 `END`

5. **执行**：初始状态是 `{'count': 0}`，图会自动循环执行，直到 `count` 达到5。

运行结果显示计数从1到5，说明循环成功执行了5次。

## 4. 状态累积：消息历史的保存

循环的核心价值在于**状态累积**。最常见的场景是保存对话历史。

在聊天机器人中，每次用户输入和AI回复都需要保存下来，这样AI才能理解上下文。

我们来构建一个简单的对话系统，每次循环都会把消息追加到历史中。

```python
from typing_extensions import TypedDict
from langgraph.graph import StateGraph, START, END

class ChatState(TypedDict):
    messages: list
    current_user_input: str

def process_message(state: ChatState):
    user_input = state['current_user_input']
    
    responses = {
        '你好': '你好！我是一个AI助手。',
        '我叫张三': '你好张三！很高兴认识你。',
        '我今天心情很好': '太好了！祝你有美好的一天！'
    }
    
    assistant_reply = responses.get(user_input, '抱歉，我不太理解。')

    new_message = {'user': user_input, 'assistant': assistant_reply}
    
    return {
        'messages': state['messages'] + [new_message],
        'current_user_input': ''
    }

def route(state: ChatState):
    if state['current_user_input']:
        return 'process'
    return END

builder = StateGraph(ChatState)
builder.add_node('process', process_message)

builder.add_edge(START, 'process')
builder.add_conditional_edges(
    'process',
    route,
    {
        'process': 'process',
        END: END
    }
)

graph = builder.compile()

state = {'messages': [], 'current_user_input': '你好'}
state = graph.invoke(state)

state['current_user_input'] = '我叫张三'
state = graph.invoke(state)

state['current_user_input'] = '我今天心情很好'
state = graph.invoke(state)

print(state['messages'])
```

### 代码解释

1. **State 定义**：`ChatState` 包含两个字段：
   - `messages`：保存所有对话历史的列表
   - `current_user_input`：当前用户输入

2. **process_message**：处理消息的核心逻辑：
   - 从状态中获取当前用户输入
   - 根据预设的规则生成助手回复
   - 将新消息追加到 `messages` 列表中（关键！）
   - 清空 `current_user_input`

3. **route**：路由函数判断是否有新输入需要处理。

4. **执行流程**：
   - 第一次调用：输入'你好'，消息列表变成 `[{'user': '你好', ...}]`
   - 第二次调用：输入'我叫张三'，消息列表变成两条记录
   - 第三次调用：输入'我今天心情很好'，消息列表变成三条记录

运行结果显示消息历史被正确累积，这就是状态持久化的基础。

## 5. MemorySaver：持久化状态存储

上面的例子中，我们手动传递状态。但在真实应用中，状态需要：

- 在多次请求之间保持
- 支持多个用户同时使用（会话隔离）
- 重启后不丢失

LangGraph 提供了 `MemorySaver` 来解决这个问题。

```python
from typing_extensions import TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.memory import MemorySaver

class ChatState(TypedDict):
    messages: list
    current_user_input: str

def process_message(state: ChatState):
    user_input = state['current_user_input']
    
    responses = {
        '你好': '你好！我是一个AI助手。',
        '我叫张三': '你好张三！很高兴认识你。',
        '我今天心情很好': '太好了！祝你有美好的一天！'
    }
    
    assistant_reply = responses.get(user_input, '抱歉，我不太理解。')

    new_message = {'user': user_input, 'assistant': assistant_reply}
    
    return {
        'messages': state['messages'] + [new_message],
        'current_user_input': ''
    }

def route(state: ChatState):
    if state['current_user_input']:
        return 'process'
    return END

builder = StateGraph(ChatState)
builder.add_node('process', process_message)

builder.add_edge(START, 'process')
builder.add_conditional_edges(
    'process',
    route,
    {
        'process': 'process',
        END: END
    }
)

memory = MemorySaver()
graph = builder.compile(checkpointer=memory)

config = {'configurable': {'thread_id': 'session_1'}}

graph.invoke({'messages': [], 'current_user_input': '你好'}, config)
graph.invoke({'current_user_input': '我叫张三'}, config)
graph.invoke({'current_user_input': '我今天心情很好'}, config)

final_state = graph.get_state(config)
print(final_state.values['messages'])
```

### 代码解释

1. **导入 MemorySaver**：从 `langgraph.checkpoint.memory` 导入。

2. **创建 MemorySaver 实例**：`memory = MemorySaver()`

3. **编译时传入 checkpointer**：`graph = builder.compile(checkpointer=memory)`

4. **配置会话ID**：
   ```python
   config = {'configurable': {'thread_id': 'session_1'}}
   ```
   `thread_id` 是会话的唯一标识，不同用户用不同的 `thread_id`。

5. **多次调用**：每次调用只传入新的输入，不需要手动传递状态。

6. **获取状态**：`graph.get_state(config)` 可以获取指定会话的当前状态。

关键区别：之前需要手动传递 `state`，现在只需传入 `config`，MemorySaver 会自动保存和恢复状态。

## 6. 多会话隔离

MemorySaver 的一个重要特性是**会话隔离**。不同的 `thread_id` 会维护独立的状态。

下面的例子演示两个用户同时使用同一个图，但各自的对话历史完全独立。

```python
from typing_extensions import TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.memory import MemorySaver

class ChatState(TypedDict):
    messages: list
    current_user_input: str

def process_message(state: ChatState):
    user_input = state['current_user_input']
    
    responses = {
        '你好': '你好！我是一个AI助手。',
        '我是Alice': '你好Alice！很高兴认识你。',
        '我是Bob': '你好Bob！很高兴认识你。'
    }
    
    assistant_reply = responses.get(user_input, '抱歉，我不太理解。')

    new_message = {'user': user_input, 'assistant': assistant_reply}
    
    return {
        'messages': state['messages'] + [new_message],
        'current_user_input': ''
    }

def route(state: ChatState):
    if state['current_user_input']:
        return 'process'
    return END

builder = StateGraph(ChatState)
builder.add_node('process', process_message)

builder.add_edge(START, 'process')
builder.add_conditional_edges(
    'process',
    route,
    {
        'process': 'process',
        END: END
    }
)

memory = MemorySaver()
graph = builder.compile(checkpointer=memory)

config_a = {'configurable': {'thread_id': 'user_a'}}
config_b = {'configurable': {'thread_id': 'user_b'}}

graph.invoke({'messages': [], 'current_user_input': '你好'}, config_a)
graph.invoke({'current_user_input': '我是Alice'}, config_a)

graph.invoke({'messages': [], 'current_user_input': 'Hi'}, config_b)
graph.invoke({'current_user_input': '我是Bob'}, config_b)

state_a = graph.get_state(config_a)
state_b = graph.get_state(config_b)

print('用户A的对话历史:')
print(state_a.values['messages'])
print()
print('用户B的对话历史:')
print(state_b.values['messages'])
```

### 代码解释

1. **创建两个配置**：
   - `config_a` 使用 `thread_id: 'user_a'`
   - `config_b` 使用 `thread_id: 'user_b'`

2. **分别调用**：
   - 用户A发送了'你好'和'我是Alice'
   - 用户B发送了'Hi'和'我是Bob'

3. **获取各自状态**：
   - 用户A的消息历史只有自己的两条消息
   - 用户B的消息历史只有自己的两条消息

运行结果清楚地展示了会话隔离：两个用户的对话历史完全独立，互不干扰。

这就是多用户聊天系统的核心原理。

## 7. 使用标准消息类型管理对话

在实际应用中，我们通常使用 LangChain 的标准消息类型（如 `HumanMessage`、`AIMessage`）来管理对话。

为了让 MemorySaver 能够自动追加消息而不是覆盖，我们需要使用 `add_messages` reducer。

这种方式的特点：
- 使用标准的消息类型，便于与LangChain组件集成
- 自动追加消息，避免手动拼接
- 方便与 LLM 集成

```python
from typing_extensions import TypedDict
from typing import Annotated
from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages
from langgraph.checkpoint.memory import MemorySaver
from langchain_core.messages import HumanMessage, AIMessage

class ChatState(TypedDict):
    messages: Annotated[list, add_messages]

def process_message(state: ChatState):
    last_message = state['messages'][-1]
    
    if isinstance(last_message, HumanMessage):
        user_input = last_message.content
        
        responses = {
            '你好': '你好！我是一个AI助手。',
            '我叫张三': '你好张三！很高兴认识你。',
        }
        
        assistant_reply = responses.get(user_input, '抱歉，我不太理解。')
        
        return {'messages': [AIMessage(content=assistant_reply)]}
    
    return state

def route(state: ChatState):
    last_message = state['messages'][-1]
    if isinstance(last_message, HumanMessage):
        return 'process'
    return END

builder = StateGraph(ChatState)
builder.add_node('process', process_message)

builder.add_edge(START, 'process')
builder.add_conditional_edges(
    'process',
    route,
    {
        'process': 'process',
        END: END
    }
)

memory = MemorySaver()
graph = builder.compile(checkpointer=memory)

config = {'configurable': {'thread_id': 'session_with_messages'}}

graph.invoke({'messages': [HumanMessage(content='你好')]}, config)
graph.invoke({'messages': [HumanMessage(content='我叫张三')]}, config)
graph.invoke({'messages': [HumanMessage(content='今天天气怎么样')]}, config)

final_state = graph.get_state(config)
for msg in final_state.values['messages']:
    if isinstance(msg, HumanMessage):
        print(f'Human: {msg.content}')
    elif isinstance(msg, AIMessage):
        print(f'AI: {msg.content}')
```

### 代码解释

1. **导入 add_messages reducer**：`from langgraph.graph.message import add_messages`
   - reducer 用于控制状态字段的更新方式
   - `add_messages` 会自动将新消息追加到列表中，而不是覆盖

2. **定义 ChatState**：使用 `Annotated[list, add_messages]` 定义消息字段
   - `Annotated` 是 Python 的类型提示工具，用于添加元数据
   - 这里告诉 LangGraph 对 `messages` 字段使用 `add_messages` reducer

3. **导入消息类型**：
   - `HumanMessage`：用户消息
   - `AIMessage`：AI回复

4. **process_message**：
   - 获取最后一条消息
   - 判断是否是用户消息
   - 如果是，生成回复并返回 `{'messages': [AIMessage(...)]}`
   - 由于使用了 `add_messages`，返回的新消息会自动追加到历史中

5. **route**：
   - 如果最后一条是用户消息，继续处理
   - 如果是AI消息，说明已经处理过了，结束

6. **调用方式**：每次传入 `{'messages': [HumanMessage(content=...)]}`
   - MemorySaver 会自动保存状态
   - `add_messages` reducer 会自动追加新消息

这种方式的优点：
- 使用标准的消息类型，便于与LangChain组件集成
- 自动追加消息，避免手动拼接
- 后续可以直接将消息列表传给LLM

## 8. 综合案例：带工具调用的循环智能体

现在我们把循环、记忆和工具调用结合起来，构建一个完整的智能体。

流程目标：
- 用户询问关于天气或时间的问题
- 智能体判断是否需要调用工具
- 如果需要，调用工具获取信息
- 如果不需要，直接回答
- 循环直到任务完成
- 使用MemorySaver保存对话历史

```python
from typing_extensions import TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.memory import MemorySaver
from langchain_core.messages import HumanMessage, AIMessage, ToolMessage

class AgentState(TypedDict):
    messages: list
    next_tool: str

def decide_tool(state: AgentState):
    last_message = state['messages'][-1]
    user_input = last_message.content
    
    print(f'用户问了：{user_input}')
    
    if '几点' in user_input or '时间' in user_input:
        print('需要调用工具：get_time')
        return {'next_tool': 'get_time'}
    elif '天气' in user_input:
        print('需要调用工具：get_weather')
        return {'next_tool': 'get_weather'}
    else:
        print('不需要调用工具，直接回答')
        return {'next_tool': None}

def call_tool(state: AgentState):
    tool_name = state['next_tool']
    
    if tool_name == 'get_time':
        result = '2024-01-15 14:30:00'
    elif tool_name == 'get_weather':
        result = '晴天，25度'
    else:
        result = '未知工具'
    
    print(f'调用工具 {tool_name}，结果：{result}')
    
    return {
        'messages': state['messages'] + [ToolMessage(content=result, tool_call_id='1')],
        'next_tool': None
    }

def summarize(state: AgentState):
    last_message = state['messages'][-1]
    
    if isinstance(last_message, ToolMessage):
        tool_result = last_message.content
        reply = f'总结回答：{tool_result}'
    else:
        reply = '抱歉，我不太理解你的问题。'
    
    print(reply)
    
    return {
        'messages': state['messages'] + [AIMessage(content=reply)]
    }

def route_after_decide(state: AgentState):
    if state['next_tool']:
        return 'call_tool'
    return 'summarize'

def route_after_summarize(state: AgentState):
    last_message = state['messages'][-1]
    if isinstance(last_message, HumanMessage):
        return 'decide_tool'
    return END

builder = StateGraph(AgentState)
builder.add_node('decide_tool', decide_tool)
builder.add_node('call_tool', call_tool)
builder.add_node('summarize', summarize)

builder.add_edge(START, 'decide_tool')
builder.add_conditional_edges(
    'decide_tool',
    route_after_decide,
    {
        'call_tool': 'call_tool',
        'summarize': 'summarize'
    }
)
builder.add_edge('call_tool', 'summarize')
builder.add_conditional_edges(
    'summarize',
    route_after_summarize,
    {
        'decide_tool': 'decide_tool',
        END: END
    }
)

memory = MemorySaver()
graph = builder.compile(checkpointer=memory)

config = {'configurable': {'thread_id': 'tool_agent_session'}}

graph.invoke({'messages': [HumanMessage(content='现在几点了')], 'next_tool': None}, config)

current_state = graph.get_state(config)
new_messages = current_state.values['messages'] + [HumanMessage(content='今天天气怎么样')]
graph.invoke({'messages': new_messages, 'next_tool': None}, config)

final_state = graph.get_state(config)
print()
print('完整对话历史:')
for msg in final_state.values['messages']:
    if isinstance(msg, HumanMessage):
        print(f'Human: {msg.content}')
    elif isinstance(msg, AIMessage):
        print(f'AI: {msg.content}')
```

### 代码解释

这个案例展示了一个完整的智能体流程：

1. **AgentState**：使用 TypedDict 定义状态，包含：
   - `messages`：消息列表
   - `next_tool`：下一个要调用的工具

2. **decide_tool**：判断是否需要调用工具
   - 如果用户问时间，返回 `{'next_tool': 'get_time'}`
   - 如果用户问天气，返回 `{'next_tool': 'get_weather'}`
   - 如果不需要工具，返回 `{'next_tool': None}`

3. **call_tool**：执行工具调用
   - 根据 `next_tool` 调用相应工具
   - 将结果追加到 `messages` 列表

4. **summarize**：总结回答
   - 如果最后是工具消息，提取结果并生成回答
   - 将回答追加到 `messages` 列表

5. **route_after_decide**：decide_tool 之后的路由
   - 如果 `next_tool` 有值，进入 `call_tool`
   - 如果 `next_tool` 为 None，进入 `summarize`

6. **route_after_summarize**：summarize 之后的路由
   - 如果最后是用户消息，回到 `decide_tool`
   - 否则结束

流程图：

```
START -> decide_tool -> [条件边] -> call_tool -> summarize
                                    ^              |
                                    |              |
                                    +--------------+
```

这个流程可以处理多轮对话，每轮都可以调用工具并保存历史。

## 9. 总结

### 核心知识点

1. **循环实现**：通过条件边让流程回到之前的节点，形成循环
2. **状态累积**：在节点中不断追加数据到状态字段（如消息列表）
3. **MemorySaver**：自动保存和恢复状态，无需手动传递
4. **会话隔离**：通过 `thread_id` 区分不同用户的会话
5. **add_messages reducer**：使用 `Annotated[list, add_messages]` 实现消息自动追加

### 关键API

| API | 作用 |
| --- | --- |
| `MemorySaver()` | 创建内存状态存储 |
| `builder.compile(checkpointer=memory)` | 编译时启用状态持久化 |
| `config = {'configurable': {'thread_id': ...}}` | 设置会话ID |
| `graph.get_state(config)` | 获取指定会话的状态 |
| `add_messages` | 自动追加消息的 reducer |

### 实践要点

- 循环的关键是路由函数返回某个已存在的节点名
- 状态累积需要在节点中返回新的状态值
- 使用 `Annotated[list, add_messages]` 可以让 MemorySaver 自动追加消息
- MemorySaver 适合开发和测试，生产环境可使用其他存储后端
- 会话隔离通过 `thread_id` 实现，必须为每个用户分配唯一ID
