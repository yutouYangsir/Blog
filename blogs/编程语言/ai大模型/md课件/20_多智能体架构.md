# 20 多智能体架构

## 学习目标
1. 理解多智能体系统的典型架构（如监督者、协作、竞争）
2. 掌握使用LangGraph设计多节点多智能体工作流
3. 能够实现多个智能体节点之间的消息传递与协作

## 1. 为什么需要多智能体

在之前的课程中，我们构建的智能体都是**单智能体**：一个智能体完成所有任务。

但真实场景中，很多任务需要**多个智能体协作**才能完成：

- **复杂任务分解**：一个任务太大，需要分给多个专业智能体
- **专业分工**：不同智能体有不同的专业知识（如代码专家、写作专家、数据分析专家）
- **协作决策**：需要多个智能体共同讨论才能做出最佳决策
- **竞争博弈**：多个智能体竞争完成同一任务

简单来说：

- **单智能体**：一个人做所有事
- **多智能体**：一个团队分工合作

## 2. 多智能体的典型架构模式

多智能体系统有几种经典的架构模式：

### 2.1 监督者模式（Supervisor Pattern）

一个监督者智能体负责协调多个工作智能体：

```
          监督者
            │
    ┌──────┼──────┬──────┐
    ▼      ▼      ▼      ▼
  智能体A 智能体B 智能体C 智能体D
```

**适用场景**：任务需要多种专业能力，监督者分配任务并汇总结果。

### 2.2 协作模式（Collaborative Pattern）

多个智能体平等协作，共同完成任务：

```
  智能体A ←→ 智能体B
     ↑          ↑
     │          │
  智能体C ←→ 智能体D
```

**适用场景**：任务需要多个智能体之间频繁交流和协同。

### 2.3 竞争模式（Competitive Pattern）

多个智能体竞争完成同一任务，胜者获得奖励：

```
  智能体A ─┐
           ├──→ 比较器 → 最佳结果
  智能体B ─┘
```

**适用场景**：需要从多个方案中选择最优解。

### 2.4 流水线模式（Pipeline Pattern）

多个智能体按顺序处理任务，像流水线一样：

```
  智能体A → 智能体B → 智能体C → 智能体D
```

**适用场景**：任务可以分解为多个顺序步骤。

### 2.5 辩论模式（Debate Pattern）

多个智能体就某个问题展开辩论，最终达成共识：

```
  正方智能体 ←→ 反方智能体
        │           │
        └────┬──────┘
             ▼
          裁判智能体
```

**适用场景**：需要深入分析某个问题的正反两面。

## 3. 第一个例子：简单的协作智能体

我们用一个简单的例子来演示多智能体协作。

场景：
- 用户提出一个问题
- 研究智能体负责收集信息
- 写作智能体负责整理成报告
- 监督者智能体负责协调整个流程

```python
from typing_extensions import TypedDict
from langgraph.graph import StateGraph, START, END
from openai import OpenAI
import os
from dotenv import load_dotenv

load_dotenv()

client = OpenAI(
    base_url=os.getenv("OPENAI_BASE_URL"),
    api_key=os.getenv("OPENAI_API_KEY")
)

def call_llm(system_prompt: str, user_prompt: str) -> str:
    response = client.chat.completions.create(
        model="qwen3.6-35b-A3b",
        messages=[
            {"role": "system", "content": system_prompt},
            {"role": "user", "content": user_prompt}
        ],
        temperature=0.7,
        max_tokens=500
    )
    return response.choices[0].message.content

class AgentState(TypedDict):
    user_question: str
    research_info: str
    report: str
    current_agent: str

def supervisor(state: AgentState):
    print(f'监督者：收到用户问题：{state["user_question"]}')
    if not state['research_info']:
        print('监督者：分配给研究智能体')
        return {'current_agent': 'research'}
    elif not state['report']:
        print('监督者：分配给写作智能体')
        return {'current_agent': 'writer'}
    else:
        print('监督者：任务完成')
        return {'current_agent': 'finish'}

def research_agent(state: AgentState):
    print(f'研究智能体：正在研究 "{state["user_question"]}"')
    system_prompt = '你是一个专业的研究助手，请针对用户问题提供详细的研究信息和分析。'
    user_prompt = f'请研究并总结关于"{state["user_question"]}"的最新信息，包括主要趋势、关键技术和未来展望。'
    research_info = call_llm(system_prompt, user_prompt)
    print(f'研究智能体：完成研究，收集到信息')
    return {'research_info': research_info}

def writer_agent(state: AgentState):
    print(f'写作智能体：正在撰写报告')
    system_prompt = '你是一个专业的报告撰写者，请根据提供的研究信息撰写结构化的报告。'
    user_prompt = f'请根据以下研究信息撰写一份完整的报告：\n\n研究信息：{state["research_info"]}'
    report = call_llm(system_prompt, user_prompt)
    print(f'写作智能体：报告完成')
    return {'report': report}

def route(state: AgentState):
    if state['current_agent'] == 'research':
        return 'research'
    elif state['current_agent'] == 'writer':
        return 'writer'
    elif state['current_agent'] == 'finish':
        return END
    return 'supervisor'

builder = StateGraph(AgentState)
builder.add_node('supervisor', supervisor)
builder.add_node('research', research_agent)
builder.add_node('writer', writer_agent)

builder.add_edge(START, 'supervisor')
builder.add_edge('research', 'supervisor')
builder.add_edge('writer', 'supervisor')
builder.add_conditional_edges(
    'supervisor',
    route,
    {
        'research': 'research',
        'writer': 'writer',
        END: END
    }
)

graph = builder.compile()

result = graph.invoke({
    'user_question': '人工智能的发展趋势',
    'research_info': '',
    'report': '',
    'current_agent': ''
})

print()
print('最终报告：')
print(result['report'])
```

### 代码解释

1. **环境配置**：
   - 加载 `.env` 文件中的 API 密钥
   - 创建 OpenAI 客户端
   - 定义 `call_llm` 函数，封装大模型调用逻辑

2. **AgentState**：定义状态包含四个字段：
   - `user_question`：用户的问题
   - `research_info`：研究智能体收集的信息
   - `report`：写作智能体生成的报告
   - `current_agent`：当前应该执行的智能体

3. **supervisor**：监督者智能体
   - 检查当前状态，决定下一步分配给哪个智能体
   - 如果没有研究信息，分配给研究智能体
   - 如果有研究信息但没有报告，分配给写作智能体
   - 如果报告已完成，标记任务结束

4. **research_agent**：研究智能体（使用真实大模型）
   - 构建系统提示词和用户提示词
   - 调用大模型获取研究结果
   - 将结果保存到 `research_info`

5. **writer_agent**：写作智能体（使用真实大模型）
   - 构建系统提示词和用户提示词
   - 调用大模型根据研究信息生成报告
   - 将结果保存到 `report`

6. **route**：路由函数
   - 根据 `current_agent` 字段决定下一步执行哪个节点

7. **图结构**：
   - START -> supervisor
   - supervisor 根据条件边分配给 research 或 writer
   - research 和 writer 执行完后都回到 supervisor
   - supervisor 判断完成后走到 END

流程图：

```
START -> supervisor
           │
    ┌──────┴──────┐
    ▼             ▼
research      writer
    │             │
    └──────┬──────┘
           ▼
       supervisor -> END
```

## 4. 流水线模式：多智能体顺序处理

流水线模式是最直观的多智能体架构，智能体按顺序处理任务。

场景：
- 用户输入一段原始文本
- 翻译智能体将其翻译成英文
- 摘要智能体生成摘要
- 情感分析智能体分析情感倾向

```python
from typing_extensions import TypedDict
from langgraph.graph import StateGraph, START, END

class PipelineState(TypedDict):
    original_text: str
    translated_text: str
    summary: str
    sentiment: str

def translate_agent(state: PipelineState):
    print(f'翻译智能体：正在翻译')
    text = state['original_text']
    translated = f'[Translated] {text}'
    print(f'翻译智能体：{translated}')
    return {'translated_text': translated}

def summarize_agent(state: PipelineState):
    print(f'摘要智能体：正在生成摘要')
    text = state['translated_text']
    summary = f'[Summary] {text[:20]}...'
    print(f'摘要智能体：{summary}')
    return {'summary': summary}

def sentiment_agent(state: PipelineState):
    print(f'情感分析智能体：正在分析情感')
    text = state['translated_text']
    if '好' in text or '高兴' in text:
        sentiment = '积极'
    elif '坏' in text or '难过' in text:
        sentiment = '消极'
    else:
        sentiment = '中性'
    print(f'情感分析智能体：情感倾向为 {sentiment}')
    return {'sentiment': sentiment}

builder = StateGraph(PipelineState)
builder.add_node('translate', translate_agent)
builder.add_node('summarize', summarize_agent)
builder.add_node('sentiment', sentiment_agent)

builder.add_edge(START, 'translate')
builder.add_edge('translate', 'summarize')
builder.add_edge('summarize', 'sentiment')
builder.add_edge('sentiment', END)

graph = builder.compile()

result = graph.invoke({
    'original_text': '今天天气很好，我很高兴。',
    'translated_text': '',
    'summary': '',
    'sentiment': ''
})

print()
print('处理结果：')
print(f'原文：{result["original_text"]}')
print(f'翻译：{result["translated_text"]}')
print(f'摘要：{result["summary"]}')
print(f'情感：{result["sentiment"]}')
```

### 代码解释

1. **PipelineState**：定义流水线的状态，包含四个字段，分别对应每个智能体的输入/输出。

2. **translate_agent**：翻译智能体
   - 接收原始文本
   - 输出翻译结果

3. **summarize_agent**：摘要智能体
   - 接收翻译后的文本
   - 输出摘要

4. **sentiment_agent**：情感分析智能体
   - 接收翻译后的文本
   - 分析情感倾向

5. **图结构**：简单的顺序流程
   - START -> translate -> summarize -> sentiment -> END

流程图：

```
START -> translate -> summarize -> sentiment -> END
```

这种模式的优点：
- 结构简单，易于理解
- 每个智能体只关注自己的任务
- 便于扩展，可以随时添加新的智能体

## 5. 竞争模式：多个智能体竞争

竞争模式中，多个智能体同时处理同一个任务，然后比较结果选择最优解。

场景：
- 用户提出一个问题
- 多个回答智能体给出不同的答案
- 评估智能体选择最佳答案

```python
from typing_extensions import TypedDict
from langgraph.graph import StateGraph, START, END

class CompetitionState(TypedDict):
    question: str
    answers: list
    best_answer: str

def answer_agent_a(state: CompetitionState):
    print(f'回答智能体A：正在回答问题')
    answer = f'A的回答：关于"{state["question"]}"，这是一个详细的回答。'
    print(f'回答智能体A：{answer}')
    return {'answers': state['answers'] + [{'agent': 'A', 'content': answer, 'score': 85}]}

def answer_agent_b(state: CompetitionState):
    print(f'回答智能体B：正在回答问题')
    answer = f'B的回答：对于"{state["question"]}"，我的见解是...'
    print(f'回答智能体B：{answer}')
    return {'answers': state['answers'] + [{'agent': 'B', 'content': answer, 'score': 92}]}

def answer_agent_c(state: CompetitionState):
    print(f'回答智能体C：正在回答问题')
    answer = f'C的回答："{state["question"]}"的答案如下...'
    print(f'回答智能体C：{answer}')
    return {'answers': state['answers'] + [{'agent': 'C', 'content': answer, 'score': 88}]}

def evaluator_agent(state: CompetitionState):
    print(f'评估智能体：正在评估所有回答')
    if not state['answers']:
        return {'best_answer': '没有回答'}

    best = max(state['answers'], key=lambda x: x['score'])
    print(f'评估智能体：最佳回答来自智能体{best["agent"]}，得分{best["score"]}')
    return {'best_answer': best['content']}

builder = StateGraph(CompetitionState)
builder.add_node('answer_a', answer_agent_a)
builder.add_node('answer_b', answer_agent_b)
builder.add_node('answer_c', answer_agent_c)
builder.add_node('evaluator', evaluator_agent)

builder.add_edge(START, 'answer_a')
builder.add_edge('answer_a', 'answer_b')
builder.add_edge('answer_b', 'answer_c')
builder.add_edge('answer_c', 'evaluator')
builder.add_edge('evaluator', END)

graph = builder.compile()

result = graph.invoke({
    'question': '什么是人工智能？',
    'answers': [],
    'best_answer': ''
})

print()
print('最佳回答：')
print(result['best_answer'])
```

### 代码解释

1. **CompetitionState**：定义竞争状态，包含：
   - `question`：用户问题
   - `answers`：所有智能体的回答列表
   - `best_answer`：评估后的最佳回答

2. **answer_agent_a/b/c**：三个回答智能体
   - 每个智能体给出自己的回答
   - 回答包含智能体标识、内容和得分
   - 将回答追加到 `answers` 列表

3. **evaluator_agent**：评估智能体
   - 比较所有回答的得分
   - 选择得分最高的回答作为最佳答案

4. **图结构**：顺序执行三个回答智能体，然后评估
   - START -> answer_a -> answer_b -> answer_c -> evaluator -> END

流程图：

```
START -> answer_a -> answer_b -> answer_c -> evaluator -> END
```

这种模式的优点：
- 可以从多个角度解决问题
- 通过竞争提高回答质量
- 易于扩展，随时可以添加新的智能体

## 6. 辩论模式：智能体之间的辩论

辩论模式中，多个智能体就某个问题展开辩论，最终达成共识或由裁判做出裁决。

场景：
- 用户提出一个有争议的问题
- 正方智能体支持某个观点
- 反方智能体反对该观点
- 裁判智能体总结辩论结果

```python
from typing_extensions import TypedDict
from langgraph.graph import StateGraph, START, END

class DebateState(TypedDict):
    question: str
    debate_history: list
    round: int
    conclusion: str

def pro_agent(state: DebateState):
    print(f'正方智能体（第{state["round"]}轮）：')
    arguments = [
        f'支持"{state["question"]}"的理由：它可以提高效率。',
        f'进一步论证：从长远来看，这是必然趋势。'
    ]
    arg = arguments[state['round'] - 1]
    print(f'  {arg}')
    return {
        'debate_history': state['debate_history'] + [{'side': '正方', 'argument': arg}],
        'round': state['round']
    }

def con_agent(state: DebateState):
    print(f'反方智能体（第{state["round"]}轮）：')
    arguments = [
        f'反对"{state["question"]}"的理由：它可能带来风险。',
        f'进一步反驳：我们需要更谨慎地对待。'
    ]
    arg = arguments[state['round'] - 1]
    print(f'  {arg}')
    new_round = state['round'] + 1
    return {
        'debate_history': state['debate_history'] + [{'side': '反方', 'argument': arg}],
        'round': new_round
    }

def judge_agent(state: DebateState):
    print(f'裁判智能体：总结辩论')
    conclusion = f'关于"{state["question"]}"的辩论总结：\n'
    for entry in state['debate_history']:
        conclusion += f'- {entry["side"]}：{entry["argument"]}\n'
    conclusion += '\n结论：双方观点都有道理，需要权衡利弊。'
    print(f'裁判智能体：{conclusion}')
    return {'conclusion': conclusion}

def after_con_route(state: DebateState):
    if state['round'] <= 2:
        return 'pro'
    return 'judge'

builder = StateGraph(DebateState)
builder.add_node('pro', pro_agent)
builder.add_node('con', con_agent)
builder.add_node('judge', judge_agent)

builder.add_edge(START, 'pro')
builder.add_edge('pro', 'con')
builder.add_conditional_edges(
    'con',
    after_con_route,
    {
        'pro': 'pro',
        'judge': 'judge'
    }
)
builder.add_edge('judge', END)

graph = builder.compile()

result = graph.invoke({
    'question': '人工智能是否应该取代人类工作？',
    'debate_history': [],
    'round': 1,
    'conclusion': ''
})

print()
print('辩论总结：')
print(result['conclusion'])
```

### 代码解释

1. **DebateState**：定义辩论状态，包含：
   - `question`：辩论的问题
   - `debate_history`：辩论历史记录
   - `round`：当前辩论轮次
   - `conclusion`：最终结论

2. **pro_agent**：正方智能体
   - 根据当前轮次给出支持观点
   - 将论点添加到辩论历史

3. **con_agent**：反方智能体
   - 根据当前轮次给出反对观点
   - 将论点添加到辩论历史

4. **judge_agent**：裁判智能体
   - 总结所有辩论内容
   - 给出最终结论

5. **after_con_route**：反方发言后的路由
   - 如果还没到第2轮，回到正方开始下一轮
   - 如果已经第2轮结束，进入裁判

6. **图结构**：
   - START -> pro -> con
   - con 根据轮次决定回到 pro 还是进入 judge
   - judge -> END

流程图：

```
START -> pro -> con
                 │
        ┌────────┴────────┐
        ▼                 ▼
       pro → con      judge -> END
```

这种模式的优点：
- 可以全面分析问题的正反两面
- 通过辩论深入探讨复杂问题
- 最终结论更加客观全面

## 7. 综合案例：多智能体协作完成复杂任务

现在我们将多种模式结合起来，构建一个复杂的多智能体系统。

场景：
- 用户提出一个数据分析需求
- 监督者智能体负责协调
- 数据收集智能体收集数据
- 数据处理智能体处理数据
- 数据分析智能体分析数据
- 报告生成智能体生成报告
- 使用MemorySaver保存状态

```python
from typing_extensions import TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.memory import MemorySaver
from openai import OpenAI
import os
from dotenv import load_dotenv

load_dotenv()

client = OpenAI(
    base_url=os.getenv("OPENAI_BASE_URL"),
    api_key=os.getenv("OPENAI_API_KEY")
)

def call_llm(system_prompt: str, user_prompt: str) -> str:
    response = client.chat.completions.create(
        model="qwen3.6-35b-A3b",
        messages=[
            {"role": "system", "content": system_prompt},
            {"role": "user", "content": user_prompt}
        ],
        temperature=0.7,
        max_tokens=500
    )
    return response.choices[0].message.content

class DataAgentState(TypedDict):
    user_request: str
    raw_data: str
    processed_data: str
    analysis_result: str
    report: str
    next_agent: str

def supervisor(state: DataAgentState):
    print(f'监督者：收到请求：{state["user_request"]}')
    
    if not state['raw_data']:
        print('监督者：分配给数据收集智能体')
        return {'next_agent': 'collect'}
    elif not state['processed_data']:
        print('监督者：分配给数据处理智能体')
        return {'next_agent': 'process'}
    elif not state['analysis_result']:
        print('监督者：分配给数据分析智能体')
        return {'next_agent': 'analyze'}
    elif not state['report']:
        print('监督者：分配给报告生成智能体')
        return {'next_agent': 'report'}
    else:
        print('监督者：任务完成')
        return {'next_agent': 'finish'}

def collect_agent(state: DataAgentState):
    print(f'数据收集智能体：正在收集数据')
    raw_data = f'原始数据：关于"{state["user_request"]}"的统计数据、趋势数据、对比数据。'
    print(f'数据收集智能体：完成数据收集')
    return {'raw_data': raw_data}

def process_agent(state: DataAgentState):
    print(f'数据处理智能体：正在处理数据')
    processed_data = f'处理后数据：清洗、转换、标准化后的"{state["user_request"]}"数据。'
    print(f'数据处理智能体：完成数据处理')
    return {'processed_data': processed_data}

def analyze_agent(state: DataAgentState):
    print(f'数据分析智能体：正在分析数据')
    
    system_prompt = '你是一个专业的数据分析师，请根据提供的数据进行深入分析。'
    user_prompt = f'请分析以下数据，找出关键发现和趋势：\n\n原始数据：{state["raw_data"]}\n\n处理后数据：{state["processed_data"]}'
    
    analysis_result = call_llm(system_prompt, user_prompt)
    
    print(f'数据分析智能体：完成数据分析')
    return {'analysis_result': analysis_result}

def report_agent(state: DataAgentState):
    print(f'报告生成智能体：正在生成报告')
    
    system_prompt = '你是一个专业的报告撰写者，请根据数据分析结果撰写结构化的报告。'
    user_prompt = f'请根据以下信息撰写一份完整的数据分析报告：\n\n请求：{state["user_request"]}\n\n分析结果：{state["analysis_result"]}'
    
    report = call_llm(system_prompt, user_prompt)
    print(f'报告生成智能体：完成报告生成')
    return {'report': report}

def route(state: DataAgentState):
    if state['next_agent'] == 'collect':
        return 'collect'
    elif state['next_agent'] == 'process':
        return 'process'
    elif state['next_agent'] == 'analyze':
        return 'analyze'
    elif state['next_agent'] == 'report':
        return 'report'
    elif state['next_agent'] == 'finish':
        return END
    return 'supervisor'

builder = StateGraph(DataAgentState)
builder.add_node('supervisor', supervisor)
builder.add_node('collect', collect_agent)
builder.add_node('process', process_agent)
builder.add_node('analyze', analyze_agent)
builder.add_node('report', report_agent)

builder.add_edge(START, 'supervisor')
builder.add_edge('collect', 'supervisor')
builder.add_edge('process', 'supervisor')
builder.add_edge('analyze', 'supervisor')
builder.add_edge('report', 'supervisor')
builder.add_conditional_edges(
    'supervisor',
    route,
    {
        'collect': 'collect',
        'process': 'process',
        'analyze': 'analyze',
        'report': 'report',
        END: END
    }
)

memory = MemorySaver()
graph = builder.compile(checkpointer=memory)

config = {'configurable': {'thread_id': 'data_analysis_session'}}

result = graph.invoke({
    'user_request': '分析过去一年的销售趋势',
    'raw_data': '',
    'processed_data': '',
    'analysis_result': '',
    'report': '',
```

## 8. 总结

### 核心知识点

1. **监督者模式**：一个监督者智能体协调多个工作智能体
2. **协作模式**：多个智能体平等协作，共同完成任务
3. **竞争模式**：多个智能体竞争，选择最优解
4. **流水线模式**：多个智能体按顺序处理任务
5. **辩论模式**：多个智能体展开辩论，最终达成共识

### 架构选择指南

| 模式 | 适用场景 | 特点 |
| --- | --- | --- |
| 监督者 | 需要多种专业能力 | 集中控制，易于管理 |
| 协作 | 需要频繁交流 | 平等协作，灵活适应 |
| 竞争 | 需要最优解 | 多方竞争，提高质量 |
| 流水线 | 可分解为顺序步骤 | 结构清晰，易于扩展 |
| 辩论 | 需要深入分析 | 全面探讨，结论客观 |

### 实践要点

- 根据任务特点选择合适的架构模式
- 智能体之间通过共享状态传递信息
- 使用监督者模式时，确保监督者逻辑清晰
- 使用MemorySaver保存状态，支持多轮交互
- 可以组合多种模式构建复杂系统
- 智能体可以调用真实大模型（如GPT、Qwen等）来生成内容
- 使用环境变量管理API密钥，确保安全性
- 通过封装call_llm函数统一管理大模型调用
