# 24_项目实战一：个人知识库问答助手

## 学习目标
1. 综合运用 LangChain 和 LangGraph 知识解决实际问题
2. 掌握项目需求分析、模块划分和技术选型
3. 开始构建第一个综合项目：个人知识库问答助手

本节课会从项目角度出发，带大家一步步设计一个“个人知识库问答助手”。它的核心能力是：**用户上传或准备一些资料，助手根据资料内容回答问题，而不是凭空编答案**。

## 1. 项目背景：为什么需要个人知识库问答助手

日常学习和工作中，我们经常会有很多资料，例如：

- 课程笔记
- 项目文档
- 公司制度
- 技术文章
- 会议记录

如果资料很多，直接人工查找会很慢。个人知识库问答助手要解决的问题就是：

> 用户提出问题，系统先从资料中找到相关内容，再基于这些内容生成回答。

这类系统通常使用 RAG 技术。RAG 的全称是 Retrieval-Augmented Generation，中文可以理解为“检索增强生成”。

通俗地说：

1. 先查资料
2. 再带着资料回答

这样可以减少大模型胡编乱造的问题。

## 2. 需求分析

做项目之前，不要急着写代码。第一步应该先想清楚：这个项目到底要解决什么问题。

本项目的基础需求如下：

| 需求 | 说明 |
| --- | --- |
| 导入资料 | 准备一批文本资料，作为知识库内容 |
| 文本切分 | 把长文档切成小段，方便检索 |
| 内容检索 | 根据用户问题找到最相关的资料片段 |
| 生成回答 | 根据检索到的资料组织答案 |
| 返回依据 | 告诉用户答案主要参考了哪些内容 |

第一版项目先做最小可用版本，也就是 MVP。我们先不处理复杂文件上传，也不接入真实数据库，而是用少量文本模拟知识库。

## 3. 项目整体流程

个人知识库问答助手的流程可以画成下面这样：

```text
准备文档 -> 切分文档 -> 建立索引 -> 用户提问 -> 检索相关片段 -> 生成答案
```

如果用生活中的例子理解：

- 准备文档：把书放进书架
- 切分文档：给书按章节拆开
- 建立索引：做目录和标签
- 用户提问：用户问“某个知识点是什么”
- 检索相关片段：先翻目录找到相关章节
- 生成答案：根据章节内容整理成自然语言回答

## 4. 技术选型

在真实项目中，可以使用下面这些技术：

| 模块 | 可选技术 | 作用 |
| --- | --- | --- |
| 文档加载 | LangChain DocumentLoader | 读取 PDF、Markdown、网页等资料 |
| 文本切分 | RecursiveCharacterTextSplitter | 把长文本切成小块 |
| 向量模型 | Embeddings | 把文本转成向量 |
| 向量数据库 | FAISS、Chroma | 存储并检索相似文本 |
| 大模型 | ChatOpenAI 或其他模型 | 根据资料生成答案 |
| 流程编排 | LangGraph | 把检索、回答、检查等步骤组织成工作流 |

为了让代码更容易运行，本节先用纯 Python 实现一个简化版 RAG。理解原理后，再过渡到 LangChain 和 LangGraph。

## 5. 第一步：准备模拟知识库

我们先不用读取外部文件，而是在代码中准备几段文本，模拟个人知识库中的资料。

```python
documents = [
    "LangChain 是一个用于开发大模型应用的框架，它提供模型调用、提示词模板、文档加载、检索问答等能力。",
    "LangGraph 是 LangChain 生态中的流程编排框架，适合构建多步骤、有状态、可分支的智能体应用。",
    "RAG 是检索增强生成技术，核心流程是先从知识库中检索相关资料，再让大模型基于资料生成答案。",
    "个人知识库问答助手可以帮助用户从自己的笔记、文档和资料中快速找到答案，减少人工查找成本。",
    "向量数据库用于存储文本向量，并根据相似度快速找到与用户问题最相关的文本片段。",
]

print(f"知识库中共有 {len(documents)} 条资料")
```

### 代码解释

这段代码完成了知识库的准备工作：

1. `documents` 是一个列表，列表里的每个字符串代表一条资料。
2. 这里的资料围绕 LangChain、LangGraph、RAG、个人知识库和向量数据库。
3. `len(documents)` 用来统计资料数量。
4. 在真实项目中，`documents` 通常不是手写的，而是从 PDF、Markdown、Word、网页或数据库中读取出来的。

这一步对应项目流程中的“准备文档”。

## 6. 第二步：文本切分

真实文档可能很长，如果直接把整篇文档拿去检索，效果通常不好。

所以我们需要把长文本切成较小的片段。这里用一个简单函数演示文本切分。

```python
def split_text(text, chunk_size=30):
    chunks = []
    for start in range(0, len(text), chunk_size):
        chunk = text[start:start + chunk_size]
        chunks.append(chunk)
    return chunks


all_chunks = []
for doc in documents:
    chunks = split_text(doc, chunk_size=30)
    all_chunks.extend(chunks)

for index, chunk in enumerate(all_chunks, start=1):
    print(f"片段 {index}: {chunk}")
```

### 代码解释

这段代码实现了一个简化版文本切分器：

1. `split_text(text, chunk_size=30)` 表示把文本按固定长度切分，每段最多 30 个字符。
2. `range(0, len(text), chunk_size)` 会生成每个片段的起始位置。
3. `text[start:start + chunk_size]` 使用字符串切片取出一小段文本。
4. `all_chunks.extend(chunks)` 把每篇文档切出来的片段合并到总列表中。
5. 最后的循环会打印所有文本片段，方便观察切分效果。

真实项目中，通常会使用 LangChain 的 `RecursiveCharacterTextSplitter`，它比这里的固定长度切分更智能，会尽量按段落、句子等边界切分。

## 7. 第三步：实现一个简单检索器

标准 RAG 通常会用向量相似度检索。为了让初学者更容易理解，我们先用“关键词重合数量”模拟检索。

规则很简单：用户问题和某个资料片段中重复出现的字越多，就认为它越相关。

```python
def simple_score(question, chunk):
    question_chars = set(question)
    chunk_chars = set(chunk)
    common_chars = question_chars & chunk_chars
    return len(common_chars)


def retrieve(question, chunks, top_k=2):
    scored_chunks = []
    for chunk in chunks:
        score = simple_score(question, chunk)
        scored_chunks.append((score, chunk))

    scored_chunks.sort(reverse=True, key=lambda item: item[0])
    return scored_chunks[:top_k]


question = "什么是 RAG？"
retrieved_chunks = retrieve(question, all_chunks, top_k=3)

for score, chunk in retrieved_chunks:
    print(f"相关度分数：{score}，内容：{chunk}")
```

### 代码解释

这段代码实现了一个简单检索器：

1. `simple_score(question, chunk)` 用来计算问题和资料片段的相关度。
2. `set(question)` 会把问题中的字符去重后放入集合。
3. `question_chars & chunk_chars` 表示取两个集合的交集，也就是问题和片段中共同出现的字符。
4. `len(common_chars)` 用共同字符数量作为相关度分数。
5. `retrieve(question, chunks, top_k=2)` 会给所有片段打分，并返回分数最高的前 `top_k` 个。
6. `scored_chunks.sort(reverse=True, key=lambda item: item[0])` 表示按照分数从高到低排序。

这个检索器很简单，但它帮助我们理解了检索阶段的本质：**从大量资料中找出最可能有用的内容**。

## 8. 第四步：根据检索结果生成答案

在真实 RAG 系统中，生成答案通常由大模型完成。

这里为了避免依赖外部 API，我们先用一个函数模拟回答生成：把检索到的资料整理成答案。

```python
def generate_answer(question, retrieved_chunks):
    context = "".join([chunk for score, chunk in retrieved_chunks])
    answer = f"问题：{question}\n\n"
    answer += "根据知识库中检索到的内容，可以参考以下信息回答：\n"
    answer += context
    answer += "\n\n总结：以上内容是从个人知识库中找到的相关资料，回答时应优先依据这些资料。"
    return answer


answer = generate_answer(question, retrieved_chunks)
print(answer)
```

### 代码解释

这段代码模拟了回答生成过程：

1. `generate_answer(question, retrieved_chunks)` 接收用户问题和检索结果。
2. `[chunk for score, chunk in retrieved_chunks]` 从检索结果中取出文本片段，忽略分数。
3. `'\n'.join(...)` 把多个片段用换行符拼接成上下文。
4. `answer += ...` 逐步拼接最终回答内容。
5. 真实项目中，这一步通常会把 `question` 和 `context` 放进提示词，然后交给大模型生成更自然、更完整的回答。

这一阶段的关键原则是：**回答要基于检索到的资料，而不是凭空生成**。

## 9. 封装成一个完整问答函数

现在我们已经有了文档片段、检索器和回答生成函数。下一步把它们封装成一个完整的 `ask_knowledge_base` 函数。

```python
def ask_knowledge_base(question, chunks, top_k=3):
    retrieved = retrieve(question, chunks, top_k=top_k)
    answer = generate_answer(question, retrieved)
    return {
        "question": question,
        "retrieved": retrieved,
        "answer": answer,
    }


result = ask_knowledge_base("LangGraph 适合做什么？", all_chunks)
print(result["answer"])
```

### 代码解释

这段代码把前面的步骤组合成一个完整功能：

1. `ask_knowledge_base` 是问答助手的主入口。用户只需要传入问题。
2. `retrieve(question, chunks, top_k=top_k)` 先从知识库片段中找相关内容。
3. `generate_answer(question, retrieved)` 再根据检索结果生成答案。
4. 函数返回一个字典，里面包含原问题、检索结果和最终答案。
5. 返回检索结果的好处是：后续可以展示“参考来源”，让用户知道答案从哪里来。

到这里，我们已经完成了一个最小版本的个人知识库问答助手。

### 代码解释

1. `RecursiveCharacterTextSplitter` 用于文本切分，`chunk_size` 控制每块大小，`chunk_overlap` 控制相邻片段之间的重叠内容。

## 12. 用 LangGraph 设计项目工作流

如果项目流程变复杂，例如要增加问题改写、检索质量检查、答案审核，就可以使用 LangGraph 编排流程。

一个基础工作流可以设计为：

```text
用户问题 -> 检索节点 -> 回答生成节点 -> 输出结果
```

```python
from typing import List, Tuple, TypedDict


class QAState(TypedDict):
    question: str
    chunks: List[str]
    retrieved: List[Tuple[int, str]]
    answer: str


def retrieve_node(state: QAState):
    retrieved = retrieve(state["question"], state["chunks"], top_k=3)
    return {"retrieved": retrieved}


def answer_node(state: QAState):
    answer = generate_answer(state["question"], state["retrieved"])
    return {"answer": answer}
```

### 代码解释

这段代码先定义 LangGraph 工作流需要的状态和节点：

1. `QAState` 表示问答流程中的共享数据。
2. `question` 保存用户问题。
3. `chunks` 保存知识库切分后的文本片段。
4. `retrieved` 保存检索结果，每个结果包含分数和文本片段。
5. `answer` 保存最终答案。
6. `retrieve_node` 是检索节点，负责调用前面写好的 `retrieve` 函数。
7. `answer_node` 是回答节点，负责调用 `generate_answer` 生成答案。

可以看到，LangGraph 节点并不神秘，本质上就是接收 State、处理数据、返回更新字段的普通函数。

## 13. 构建 LangGraph 工作流

下面把检索节点和回答节点连接起来。

如果当前环境没有安装 LangGraph，可以先运行：`%pip install langgraph`。

```python
# 如果没有安装 LangGraph，取消下一行注释后运行
# %pip install langgraph

from langgraph.graph import END, START, StateGraph


qa_workflow = StateGraph(QAState)

qa_workflow.add_node("retrieve", retrieve_node)
qa_workflow.add_node("answer", answer_node)

qa_workflow.add_edge(START, "retrieve")
qa_workflow.add_edge("retrieve", "answer")
qa_workflow.add_edge("answer", END)

qa_app = qa_workflow.compile()
```

### 代码解释

这段代码把问答流程编排成 LangGraph 工作流：

1. `StateGraph(QAState)` 创建一张基于 `QAState` 的流程图。
2. `add_node("retrieve", retrieve_node)` 添加检索节点。
3. `add_node("answer", answer_node)` 添加回答生成节点。
4. `add_edge(START, "retrieve")` 表示从检索节点开始。
5. `add_edge("retrieve", "answer")` 表示检索完成后进入回答节点。
6. `add_edge("answer", END)` 表示回答生成后流程结束。
7. `compile()` 把流程图编译成可以调用的 `qa_app`。

这就是一个最小 LangGraph 版个人知识库问答流程。

## 14. 运行 LangGraph 问答助手

现在传入问题和知识库片段，运行整个工作流。

```python
initial_state = {
    "question": "个人知识库问答助手有什么作用？",
    "chunks": all_chunks,
    "retrieved": [],
    "answer": "",
}

final_state = qa_app.invoke(initial_state)
print(final_state["answer"])
```

### 代码解释

这段代码运行了 LangGraph 工作流：

1. `initial_state` 是初始状态，包含用户问题、知识库片段、空的检索结果和空答案。
2. `qa_app.invoke(initial_state)` 启动工作流。
3. 数据会先进入 `retrieve_node`，生成 `retrieved`。
4. 然后进入 `answer_node`，生成 `answer`。
5. 最终返回 `final_state`，我们打印其中的 `answer`。

这个例子说明：LangGraph 适合把多个处理步骤组织成清晰、可维护的项目流程。

## 15. 项目可以如何继续升级

当前版本只是教学版 MVP，后续可以从这些方向升级：

1. 支持读取 PDF、Markdown、Word 等真实文件。
