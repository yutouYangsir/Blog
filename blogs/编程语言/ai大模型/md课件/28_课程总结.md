3. 规划后续自主学习路径和实践建议

本节课不是学习一个全新的技术点，而是把前面学过的内容串起来，帮助大家形成一张完整的“AI 智能体知识地图”。

## 1. 这门课到底学了什么

如果用一句话总结这门课：

> 我们学习了如何把大模型从“聊天机器人”升级为“能够使用工具、执行流程、完成任务的智能体”。

普通大模型更像一个会回答问题的人，而智能体更像一个会办事的助手。它不只是生成文字，还可以：

- 理解用户目标
- 拆解任务步骤
- 调用外部工具
- 读取和检索资料
- 根据中间结果继续决策
- 最终交付完整结果

所以，智能体的核心不是“模型有多聪明”，而是“模型能否被组织进一个可靠的工作流程中”。

## 2. AI 智能体的核心知识地图

可以把整个课程内容分成 6 个层次：

| 层次 | 核心内容 | 通俗理解 |
| --- | --- | --- |
| 大模型基础 | Prompt、模型调用、消息格式 | 让模型听懂我们的问题 |
| LangChain | 链、提示词、工具、RAG | 把模型能力组件化 |
| 工具调用 | 搜索、计算、文件读取、API | 让模型能使用外部能力 |
| RAG 知识库 | 文档切分、向量检索、基于资料回答 | 让模型先查资料再回答 |
| LangGraph | State、Node、Edge、条件分支 | 把智能体流程画成流程图 |
| 项目实战 | 知识库助手、多工具智能体 | 把知识点组合成完整应用 |

学习时不要只记住某个库的 API，更重要的是理解这些模块分别解决什么问题。

## 3. 回顾一：Prompt 是智能体的起点

Prompt 可以理解为我们给大模型的任务说明书。

一个好的 Prompt 通常会说明：

1. 你是谁：模型要扮演什么角色
2. 你要做什么：具体任务是什么
3. 你依据什么：是否需要参考资料
4. 你怎么输出：输出格式有什么要求

下面用一个简单函数模拟 Prompt 拼接。

```python
def build_prompt(role, task, context, output_format):
    prompt = f"角色：{role}\n"
    prompt += f"任务：{task}\n"
    prompt += f"参考资料：{context}\n"
    prompt += f"输出格式：{output_format}"
    return prompt


prompt = build_prompt(
    role="AI 智能体课程助教",
    task="解释什么是工具调用",
    context="工具调用是指模型根据任务选择并使用外部函数或 API。",
    output_format="用三句话通俗解释",
)

print(prompt)
```

### 代码解释

这段代码用于复习 Prompt 的基本组成：

1. `build_prompt` 是一个提示词构造函数。
2. `role` 表示模型扮演的角色，例如课程助教、数据分析师、代码助手。
3. `task` 表示模型要完成的具体任务。
4. `context` 表示参考资料，能够减少模型凭空发挥。
5. `output_format` 表示输出格式要求，可以让答案更稳定。
6. 函数内部通过字符串拼接生成完整 Prompt。

真实项目中，Prompt 往往不是随便写一句话，而是要像写任务说明书一样清晰。

## 4. 回顾二：工具调用让智能体拥有外部能力

大模型擅长理解和生成语言，但不擅长所有事情。

例如数学计算、实时搜索、文件读取、数据库查询等任务，更适合交给工具完成。

工具调用的基本流程是：

```text
用户问题 -> 判断是否需要工具 -> 选择工具 -> 执行工具 -> 整理结果
```

下面用一个简化例子复习工具选择和调用。

```python
def calculate(expression):
    return eval(expression)


def search_knowledge(keyword):
    knowledge = {
        "LangChain": "LangChain 用于构建大模型应用。",
        "LangGraph": "LangGraph 用于编排多步骤智能体流程。",
    }
    return knowledge.get(keyword, "没有找到相关知识。")


def simple_tool_agent(question):
    if "计算" in question:
        expression = question.replace("计算", "").strip()
        result = calculate(expression)
        return f"我使用了计算工具，结果是：{result}"

    if "LangGraph" in question:
        result = search_knowledge("LangGraph")
        return f"我使用了知识查询工具，结果是：{result}"

    return "这个问题暂时不需要调用工具。"


print(simple_tool_agent("计算 25 * 4 + 8"))
print(simple_tool_agent("LangGraph 是什么？"))
```

### 代码解释

这段代码复习了工具调用的基本思想：

1. `calculate(expression)` 是计算工具，负责执行数学表达式。
2. `search_knowledge(keyword)` 是知识查询工具，负责从字典中查找资料。
3. `simple_tool_agent(question)` 是一个简单智能体入口。
4. 如果问题中包含“计算”，就提取表达式并调用计算工具。
5. 如果问题中包含 `LangGraph`，就调用知识查询工具。
6. 最终返回时，会说明使用了哪个工具以及工具结果。

这里为了复习写得很简单。真实项目中，不建议直接对用户输入使用 `eval`，应使用更安全的计算库或严格校验。

## 5. 回顾三：RAG 让模型基于资料回答

RAG 是构建知识库问答系统时非常重要的技术。

它解决的问题是：大模型不知道你的私有资料，也可能记错公开知识。

RAG 的思路很简单：

1. 先把资料放入知识库
2. 用户提问时先检索相关资料
3. 再让模型基于检索资料回答

下面用纯 Python 复习一个最小 RAG 流程。

```python
documents = [
    "RAG 的核心是先检索资料，再基于资料生成答案。",
    "LangChain 提供文档加载、文本切分、检索器和链等能力。",
    "LangGraph 适合构建有状态、多步骤、可分支的智能体流程。",
]


def retrieve_by_keyword(question, documents):
    scored_docs = []
    for doc in documents:
        score = len(set(question) & set(doc))
        scored_docs.append((score, doc))

    scored_docs.sort(reverse=True, key=lambda item: item[0])
    return scored_docs[0][1]


def rag_answer(question):
    context = retrieve_by_keyword(question, documents)
    return f"问题：{question}\n参考资料：{context}\n回答：请优先根据参考资料作答。"


print(rag_answer("RAG 的核心流程是什么？"))
```

### 代码解释

这段代码复习了 RAG 的最小流程：

1. `documents` 模拟知识库中的资料。
2. `retrieve_by_keyword` 是简化检索器，会给每条资料计算相关度分数。
3. `set(question) & set(doc)` 表示问题和文档中共同出现的字符。
4. `scored_docs.sort(...)` 按分数从高到低排序。
5. `rag_answer(question)` 先检索最相关资料，再把资料作为参考内容组织成回答。

真实 RAG 项目通常会把关键词检索换成向量检索，把简单回答拼接换成大模型生成。

## 6. 回顾四：LangGraph 让流程更清晰

当智能体只有一步时，普通函数就够了。

但当智能体需要多步骤执行、条件判断、循环反思、工具协作时，就需要更清晰的流程编排。

LangGraph 的核心概念可以简单理解为：

| 概念 | 作用 | 通俗理解 |
| --- | --- | --- |
| State | 保存流程中的数据 | 任务档案袋 |
| Node | 一个处理步骤 | 流程图里的方框 |
| Edge | 节点之间的连接 | 流程图里的箭头 |
| Conditional Edge | 条件分支 | 根据情况走不同路线 |

下面不用依赖 LangGraph，先用普通 Python 模拟这种状态流转思想。

```python
def plan_node(state):
    goal = state["goal"]
    state["plan"] = [f"理解目标：{goal}", "执行任务", "汇总结果"]
    return state


def execute_node(state):
    state["result"] = [f"已完成：{step}" for step in state["plan"]]
    return state


def summary_node(state):
    state["answer"] = "\n".join(state["result"])
    return state


state = {"goal": "复习 AI 智能体课程"}
state = plan_node(state)
state = execute_node(state)
state = summary_node(state)

print(state["answer"])
```

### 代码解释

这段代码用普通 Python 模拟 LangGraph 的状态流转：

1. `state` 是一个字典，相当于工作流中的共享状态。
2. `plan_node(state)` 模拟规划节点，会根据目标生成计划。
3. `execute_node(state)` 模拟执行节点，会执行计划中的每个步骤。
4. `summary_node(state)` 模拟汇总节点，会把结果整理成最终答案。
5. 每个节点都接收 `state`，修改后再返回 `state`。

LangGraph 做的事情更规范、更强大，但底层思想就是让数据沿着流程图一步步流动。

## 7. 一个智能体项目的标准开发流程

开发智能体项目时，可以按照下面的步骤推进：

1. 明确用户需求：用户到底要解决什么问题
2. 设计输入输出：用户输入什么，系统输出什么
3. 拆分功能模块：需要模型、工具、检索还是工作流
4. 先做最小版本：用简单规则和模拟数据跑通流程
5. 替换真实能力：接入真实模型、数据库、搜索 API 等
6. 增加调试日志：观察每一步中间结果
7. 优化稳定性：处理异常、补充测试、改进提示词

初学者最容易犯的错误是：一上来就想做完整系统。更推荐先做 MVP，再逐步升级。

## 8. 智能体常见项目类型

学完本课程后，可以尝试这些项目方向：

| 项目类型 | 能力重点 | 示例 |
| --- | --- | --- |
| 知识库问答助手 | RAG、文档检索 | 课程资料问答、企业制度问答 |
| 多工具助手 | 工具选择、工具调用 | 搜索 + 计算 + 文件读取助手 |
| 自动报告生成器 | 任务分解、结果汇总 | 周报生成、调研报告生成 |
| 数据分析智能体 | 代码执行、图表生成 | 自动分析表格并输出结论 |
| 工作流智能体 | LangGraph、条件分支 | 审核流程、客服分流、任务调度 |
| 多智能体协作 | 角色分工、结果协同 | 产品经理 + 开发 + 测试协作 |

建议从知识库问答和多工具助手开始，因为它们最容易理解，也最接近真实应用。

## 9. AI 智能体的发展趋势

AI 智能体还在快速发展，值得关注的方向包括：

1. **更强的工具调用能力**：模型会更准确地选择工具、填写参数、处理工具错误。
2. **更可靠的工作流编排**：复杂任务会越来越依赖 LangGraph 这类流程框架。
3. **多模态智能体**：智能体不仅处理文字，还能理解图片、语音、视频和表格。
4. **企业级知识库**：RAG 会和权限控制、审计、数据治理结合得更紧密。
5. **多智能体协作**：多个角色智能体分工合作，完成更复杂的任务。
6. **本地化和私有化部署**：越来越多企业会关注数据安全和私有模型部署。

但无论技术怎么变，底层能力仍然离不开：需求分析、任务拆解、工具设计、流程控制和结果验证。

## 12. 最后一个综合复习示例

下面用一个小例子把 Prompt、工具调用、RAG 和流程编排思想合在一起。

这个示例仍然是教学版，目标是帮助大家看清完整结构。

```python
course_docs = [
    "智能体可以调用工具完成搜索、计算、文件读取等任务。",
    "RAG 可以让智能体基于知识库资料回答问题。",
    "LangGraph 可以把智能体任务拆成多个节点并按流程执行。",
]


def course_retriever(question):
    best_doc = max(course_docs, key=lambda doc: len(set(question) & set(doc)))
    return best_doc


def course_calculator(expression):
    return eval(expression)


def final_review_agent(question):
    if "计算" in question:
        expression = question.replace("计算", "").strip()
        result = course_calculator(expression)
        return f"我判断这是计算任务，调用计算工具后得到：{result}"

    context = course_retriever(question)
    prompt = build_prompt(
        role="AI 智能体课程总结助手",
        task=f"回答问题：{question}",
        context=context,
        output_format="先给结论，再给一句解释",
    )
    return prompt


print(final_review_agent("RAG 有什么作用？"))
print("-" * 40)
print(final_review_agent("计算 18 * 6 + 2"))
```

### 代码解释

这个综合示例把多个知识点串联起来：

1. `course_docs` 是一个小型课程知识库。
2. `course_retriever(question)` 根据问题从知识库中找最相关的资料。
3. `course_calculator(expression)` 是计算工具。
4. `final_review_agent(question)` 是综合复习智能体入口。
5. 如果问题中包含“计算”，智能体会调用计算工具。
6. 如果不是计算任务，智能体会先检索课程资料，再调用前面写过的 `build_prompt` 生成提示词。
7. 这个流程体现了智能体的基本思想：先判断任务类型，再选择合适能力，最后组织输出。

真实项目中，可以把这里的 `return prompt` 换成真实大模型调用，让模型基于 Prompt 生成最终回答。

## 13. 课程总结

这门课的重点不是让大家记住所有 API，而是建立一套解决智能体问题的思维方式：

1. 先理解用户目标，再决定系统流程。
2. 能用普通函数解决的，先用普通函数跑通。
3. 需要模型生成时，再接入大模型。
4. 需要外部能力时，封装成工具。
5. 需要资料依据时，使用 RAG。
6. 需要多步骤流程时，使用 LangGraph。
7. 需要稳定上线时，补充日志、测试、异常处理和监控。

真正的智能体开发，不是把所有新技术堆在一起，而是根据问题选择最合适、最简单、最可靠的方案。
