# 17 节点与边

## 学习目标
1. 掌握添加节点（`add_node`）和添加边（`add_edge`）的方法
2. 理解 `START` 和 `END` 在图中的含义
3. 能够构建包含多个节点的顺序执行图
4. 理解节点负责做事、边负责决定顺序的分工
5. 能够看懂并修改一个简单的图流程

## 1. 为什么要单独讲节点与边

在前两节中，我们已经接触过图结构和状态管理。现在要进一步回答一个更基础的问题：

**一张图到底是怎么拼出来的？**

答案就是：

- 用 **节点（Node）** 表示每一步做什么
- 用 **边（Edge）** 表示下一步往哪里走

也就是说：

- 节点负责‘干活’
- 边负责‘指路’

你可以把它想象成一张旅游路线图：

- 景点 = 节点
- 景点之间的道路 = 边
- 你游览的先后顺序 = 图的执行顺序

如果没有节点，图里就没有真正执行的步骤；如果没有边，这些步骤之间就连不起来。

## 2. 节点是什么

在 LangGraph 中，节点通常就是一个 Python 函数。

这个函数会：

1. 接收当前状态 `state`
2. 处理数据
3. 返回要更新的状态字段

例如一个节点可以做这些事：

- 给数字加 1
- 拼接一段字符串
- 计算总价
- 调用大模型
- 调用工具

所以，节点本质上就是流程中的‘处理步骤’。

一个图里可以有一个节点，也可以有很多节点。节点越多，流程通常越细。

## 3. 边是什么

边表示节点和节点之间的连接关系。

如果说节点回答的是：

> 这一步做什么？

那么边回答的就是：

> 做完这一步以后，下一步去哪？

例如：

```
START -> node_a -> node_b -> END
```

这里就有三条边：

- `START -> node_a`
- `node_a -> node_b`
- `node_b -> END`

所以，边并不负责处理数据，它只负责规定执行顺序。

## 4. `START` 和 `END` 是什么

在 LangGraph 中，我们通常会看到两个特殊标记：

- `START`：图的起点
- `END`：图的终点

它们不是普通业务节点，而是系统提供的特殊位置。

你可以把它们理解成：

- `START` = 流程从哪里进入
- `END` = 流程在哪里结束

注意：

- `START` 不负责处理数据
- `END` 也不负责处理数据
- 它们的作用只是帮助我们把流程的起点和终点标出来

因此，很多图都长这样：

```
START -> 第一个节点 -> 第二个节点 -> END
```

## 5. 第一个例子：一个节点的最小图

先从最简单的图开始，只放一个节点。

流程如下：

```
START -> greet -> END
```

也就是说：

1. 流程从 `START` 进入
2. 执行 `greet` 节点
3. 执行完后直接结束

```python
from typing_extensions import TypedDict
from langgraph.graph import StateGraph, START, END

class HelloState(TypedDict):
    name: str
    message: str

def greet(state: HelloState):
    return {'message': f'你好，{state["name"]}！'}

builder = StateGraph(HelloState)
builder.add_node('greet', greet)
builder.add_edge(START, 'greet')
builder.add_edge('greet', END)

graph = builder.compile()
result = graph.invoke({'name': '小明', 'message': ''})
print(result)
```

### 代码解释

这个例子非常短，但已经完整包含了节点与边的核心写法。

#### `class HelloState(TypedDict)`
这里定义了图中的状态结构，包含两个字段：

- `name`：输入的人名
- `message`：节点生成的问候语

#### `def greet(state)`
这就是一个节点函数。它读取 `name`，然后生成一句问候语，写入 `message`。

也就是说，这个节点真正做的事情是：

```text
读取名字 -> 生成问候 -> 写回状态
```

#### `builder.add_node('greet', greet)`
这是把节点加入图中的关键代码。

它的意思是：

- 节点名字叫 `greet`
- 节点实际执行的函数是 `greet`

你可以把前面的字符串 `'greet'` 理解为节点标签，把后面的函数 `greet` 理解为节点的工作内容。

#### `builder.add_edge(START, 'greet')`
表示流程从起点进入 `greet` 节点。

#### `builder.add_edge('greet', END)`
表示执行完 `greet` 节点之后，流程直接结束。

#### 整体流程
整个图的执行路径就是：

```
START -> greet -> END
```

这是最小的完整图，也是理解节点与边的最好起点。

## 6. 两个节点的顺序图

一个节点的图很简单，但很多实际流程至少会有两个步骤。

下面我们做一个两步流程：

1. 先生成问候语
2. 再给问候语后面补一句欢迎信息

流程如下：

```
START -> make_greeting -> add_welcome -> END
```

```python
from typing_extensions import TypedDict
from langgraph.graph import StateGraph, START, END

class WelcomeState(TypedDict):
    name: str
    greeting: str
    final_text: str

def make_greeting(state: WelcomeState):
    return {'greeting': f'你好，{state["name"]}！'}

def add_welcome(state: WelcomeState):
    return {'final_text': state['greeting'] + ' 欢迎学习 LangGraph。'}

builder = StateGraph(WelcomeState)
builder.add_node('make_greeting', make_greeting)
builder.add_node('add_welcome', add_welcome)

builder.add_edge(START, 'make_greeting')
builder.add_edge('make_greeting', 'add_welcome')
builder.add_edge('add_welcome', END)

graph = builder.compile()
result = graph.invoke({
    'name': '小红',
    'greeting': '',
    'final_text': ''
})

print(result)
print(result['final_text'])
```

### 代码解释

这个例子比前一个例子多了一个节点，因此也多了一条边。

#### 两个节点分别做什么
- `make_greeting`：生成问候语
- `add_welcome`：在问候语后面追加欢迎信息

这两个节点就像工厂里的两个工位：

- 第一个工位先加工出半成品
- 第二个工位接着加工成完整成品

#### 为什么这里要有三条边
因为整个流程要从头走到尾，所以必须把三段路径都写出来：

1. `START -> make_greeting`
2. `make_greeting -> add_welcome`
3. `add_welcome -> END`

少写任何一条，图的路径都会不完整。

#### `add_edge('make_greeting', 'add_welcome')` 的意义
这行代码非常关键，它表达的是：

> 第一个节点做完以后，不是结束，而是继续把结果交给第二个节点。

所以我们可以说：

- 节点负责定义每一步做什么
- 边负责把这些步骤串成一条完整路线

#### 整个执行过程
执行时，状态会这样流动：

1. 初始状态进入 `make_greeting`
2. 生成 `greeting='你好，小红！'`
3. 再进入 `add_welcome`
4. 生成 `final_text='你好，小红！ 欢迎学习 LangGraph。'`
5. 最后进入 `END`

这就是最典型的多节点顺序图。

## 7. 三个节点的顺序图

为了进一步理解边的作用，我们再看一个三个节点的例子。

流程目标：

1. 输入一个数字
2. 先加 2
3. 再乘 3
4. 最后减 1

流程图如下：

```
START -> add_two -> multiply_three -> minus_one -> END
```

```python
from typing_extensions import TypedDict
from langgraph.graph import StateGraph, START, END

class NumberState(TypedDict):
    value: int

def add_two(state: NumberState):
    return {'value': state['value'] + 2}

def multiply_three(state: NumberState):
    return {'value': state['value'] * 3}

def minus_one(state: NumberState):
    return {'value': state['value'] - 1}

builder = StateGraph(NumberState)
builder.add_node('add_two', add_two)
builder.add_node('multiply_three', multiply_three)
builder.add_node('minus_one', minus_one)

builder.add_edge(START, 'add_two')
builder.add_edge('add_two', 'multiply_three')
builder.add_edge('multiply_three', 'minus_one')
builder.add_edge('minus_one', END)

graph = builder.compile()
result = graph.invoke({'value': 4})
print(result)
```

### 代码解释

这个例子的重点是：**节点一多，边就必须更清楚地把顺序连接起来。**

#### 三个节点的分工
- `add_two`：把数字加 2
- `multiply_three`：把结果乘 3
- `minus_one`：把结果减 1

每个节点都只做一件非常明确的事情。

#### 四条边的作用
这里总共有四条边：

- `START -> add_two`
- `add_two -> multiply_three`
- `multiply_three -> minus_one`
- `minus_one -> END`

从这个例子你能很明显地看出：

- 节点数量增加，边的数量通常也会跟着增加
- 边并不是可有可无的，它是图的骨架

#### 为什么顺序会影响结果
如果初始值是 `4`，按当前顺序执行：

1. `4 + 2 = 6`
2. `6 * 3 = 18`
3. `18 - 1 = 17`

最终结果是：

```python
{'value': 17}
```

如果你把边的顺序改掉，例如先乘再加，结果就会完全不同。

这说明一件事：

**边不仅是在连线，它其实是在定义业务流程的顺序逻辑。**

## 8. 常见错误：只加节点，不连边

初学者最常见的错误之一，就是把节点都加进去了，但忘了把它们连起来。

例如你可能写了：

- `add_node('a', node_a)`
- `add_node('b', node_b)`
- `add_node('c', node_c)`

但如果没有边，图并不知道该怎么走。

所以一定要记住：

- 节点 = 把工位摆出来
- 边 = 把工位之间的传送带接起来

只有节点没有边，就像车间里摆了很多机器，但它们之间没有流水线，产品根本流不过去。

## 9. 常见错误：边的顺序写错

另一个常见错误，是边都写了，但顺序写错了。

比如本来你想要：

```
START -> add_two -> multiply_three -> minus_one -> END
```

结果却写成：

```
START -> multiply_three -> add_two -> minus_one -> END
```

这样虽然图也能运行，但业务逻辑已经变了。

所以在写边的时候，不要只关心‘能不能连上’，更要关心‘是不是按我想要的顺序连上’。

## 10. 节点与边的分工总结

到这里，你可以把节点与边的关系总结成一句话：

**节点定义处理步骤，边定义执行路径。**

更具体一点：

| 组件 | 作用 | 你可以怎么理解 |
| --- | --- | --- |
| Node（节点） | 做具体工作 | 流程中的工位 |
| Edge（边） | 决定下一步去哪 | 工位之间的路线 |
| START | 流程入口 | 从哪里开始 |
| END | 流程出口 | 在哪里结束 |

只要把这四个角色分清楚，写简单的图就不会乱。

## 11. 本节小结

本节最重要的内容有五点：

1. **节点就是处理步骤，通常由函数表示**
2. **边就是连接关系，负责决定执行顺序**
3. **`START` 是起点，`END` 是终点**
4. **节点越多，越要靠边把流程顺序明确写出来**
5. **图能不能正确运行，不仅取决于节点有没有写对，也取决于边有没有连对**

理解了节点与边，后面再学条件边、分支流程、循环流程时，你会更容易看懂整张图是怎么运转的。
