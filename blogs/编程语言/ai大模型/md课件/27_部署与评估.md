# 27 部署与评估

## 学习目标
1. 了解智能体应用的部署方式，例如本地函数、本地 API、Docker 和云平台
2. 掌握智能体效果评估的常见指标和方法
3. 学会用测试集评估智能体的稳定性和准确性
4. 理解日志、追踪和 LangSmith 在智能体项目中的作用
5. 能够为一个智能体项目设计简单的上线检查流程

前面我们已经完成了一个带交互界面的智能体项目。本节课要解决的问题是：**项目写完以后，怎么交付给别人使用？怎么判断它运行得好不好？**

## 1. 为什么要学习部署与评估

很多初学者做智能体项目时，会停留在 notebook 能运行的阶段。

但真实项目还需要回答三个问题：

1. **别人怎么使用它？**
2. **它回答得好不好？**
3. **出问题时怎么排查？**

这三个问题分别对应：

| 问题 | 对应能力 |
| --- | --- |
| 怎么使用 | 部署 |
| 好不好用 | 评估 |
| 怎么排查 | 追踪与日志 |

所以，智能体开发不是写完代码就结束。真正完整的流程应该是：

```text
开发 -> 测试 -> 评估 -> 部署 -> 监控 -> 迭代
```

本节会用通俗方式把这条链路讲清楚。

## 2. 智能体常见部署方式

部署可以理解为：**把只能自己运行的代码，变成别人也能使用的服务。**

常见部署方式有下面几种：

| 部署方式 | 适合场景 | 特点 |
| --- | --- | --- |
| 本地函数 | 学习、测试、内部脚本 | 最简单，但只能在代码里调用 |
| 命令行程序 | 工具型项目、个人使用 | 可以通过终端交互 |
| 本地 API | 前后端分离、系统集成 | 其他程序可以通过 HTTP 调用 |
| Docker | 统一环境、方便迁移 | 避免“我电脑能跑，你电脑不能跑” |
| 云平台 | 正式上线、多用户访问 | 稳定性更高，但配置更复杂 |

初学时不要一上来就追求复杂部署。

推荐顺序是：

```text
函数调用 -> 命令行 -> 本地 API -> Docker -> 云平台
```

每一步都是在上一层基础上增加一点工程化能力。

## 3. 准备一个可部署的智能体核心函数

部署前最重要的一件事是：**把核心逻辑封装成一个清晰的函数。**

不管后面是接命令行、Web API，还是云服务，最终都应该调用同一个核心函数。

下面我们用一个简化版学习助手作为示例。

```python
def run_learning_assistant(user_input):
    if '计划' in user_input or '安排' in user_input:
        intent = 'plan'
        response = '建议先学习 State、Node、Edge，再学习条件边、工具调用和项目实战。'
    elif '解释' in user_input or '什么是' in user_input:
        intent = 'explain'
        response = 'LangGraph 可以理解为用图结构组织智能体流程的框架。'
    else:
        intent = 'chat'
        response = '我可以帮你制定学习计划、解释概念或梳理项目思路。'

    return {
        'input': user_input,
        'intent': intent,
        'response': response
    }

result = run_learning_assistant('帮我制定 LangGraph 学习计划')
print(result)
```

### 代码解释

这段代码是一个最小可部署单元。

#### `run_learning_assistant(user_input)`
这个函数接收用户输入，然后返回一个结构化结果。

它没有直接使用 `input()`，也没有直接打印最终答案。

这样做是为了方便部署。因为不同界面拿到结果后，可以用自己的方式展示：

- 命令行可以 `print`
- Web API 可以返回 JSON
- 前端页面可以渲染到聊天窗口

#### 为什么返回字典
函数返回：

```python
{
    'input': user_input,
    'intent': intent,
    'response': response
}
```

这比只返回一个字符串更适合工程项目。

因为调用方不仅能拿到回复，还能看到系统识别出的意图，方便调试和评估。

#### 部署前的关键原则
无论项目内部多复杂，都建议对外提供一个简单入口。

可以把它理解成智能体项目的“总开关”。

## 4. 本地 API 部署的基本思路

API 部署的意思是：让其他程序通过 HTTP 请求调用你的智能体。

例如前端页面可以发送：

```text
POST /chat
{"message": "帮我制定学习计划"}
```

服务端返回：

```text
{"response": "建议先学习 State、Node、Edge..."}
```

下面先不用 FastAPI，直接用一个普通函数模拟 API 处理过程。

```python
def chat_api_handler(request_json):
    user_message = request_json.get('message', '')

    if not user_message.strip():
        return {
            'ok': False,
            'error': 'message 不能为空'
        }

    result = run_learning_assistant(user_message)

    return {
        'ok': True,
        'data': result
    }

request = {'message': '解释一下什么是 LangGraph'}
response = chat_api_handler(request)
print(response)
```

### 代码解释

这段代码模拟了一个 API 接口。

#### `request_json`
它代表外部系统传来的请求数据。

真实 API 中，这个数据通常来自 HTTP 请求体。

#### `request_json.get('message', '')`
这行代码从请求中取出用户消息。

如果请求里没有 `message`，就默认使用空字符串。

#### 空输入检查
如果用户没有传有效内容，接口返回：

```python
{'ok': False, 'error': 'message 不能为空'}
```

这是部署时常见的边界检查。

#### 调用核心函数
真正处理智能体逻辑的是：

```python
result = run_learning_assistant(user_message)
```

API 层不应该写太多智能体逻辑，它只负责接收请求、调用核心函数、返回结果。

#### 为什么这样分层
分层后，项目会更容易维护：

- 智能体逻辑改动，不影响 API 格式
- API 部署方式改动，不影响智能体核心
- 测试时可以单独测试核心函数，也可以测试接口函数

## 5. FastAPI 部署示意

真实项目中，经常会用 FastAPI 把智能体包装成 HTTP 服务。

下面是示意代码。这里放在 Markdown 中展示，不要求你现在必须运行。

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class ChatRequest(BaseModel):
    message: str

@app.post('/chat')
def chat(request: ChatRequest):
    result = run_learning_assistant(request.message)
    return result
```

如果保存为 `app.py`，通常可以用下面命令启动：

```bash
uvicorn app:app --host 0.0.0.0 --port 8000
```

启动后，其他程序就可以通过接口调用智能体。

## 6. Docker 和云平台部署怎么理解

当项目只在自己电脑上运行时，问题通常不大。

但交给别人运行时，经常会出现：

- Python 版本不同
- 依赖包没安装
- 环境变量没配置
- 系统路径不一致

Docker 的作用就是把运行环境打包起来。

可以把 Docker 镜像理解成一个“装好环境的盒子”。别人只要运行这个盒子，就能得到接近一致的环境。

云平台部署则是在远程服务器上运行这个应用，让更多用户可以访问。

一个常见上线链路是：

```text
本地开发 -> 写 requirements.txt -> 写 Dockerfile -> 构建镜像 -> 部署到云服务器
```

本课程重点是智能体开发，所以这里只需要理解部署思路，不要求一次掌握所有运维细节。

## 7. 为什么要评估智能体

部署解决的是“能不能给别人用”。

评估解决的是“用得好不好”。

智能体评估通常关注：

| 指标 | 含义 | 示例 |
| --- | --- | --- |
| 正确性 | 回答是否正确 | 是否解释对了概念 |
| 相关性 | 是否回答了用户问题 | 问学习计划，不要回复天气 |
| 完整性 | 回答是否覆盖关键点 | 学习计划是否有步骤 |
| 稳定性 | 多次运行是否表现一致 | 同类问题是否走同类分支 |
| 成本 | 调用模型的费用和耗时 | token、延迟、API 成本 |
| 安全性 | 是否避免危险输出 | 不泄露密钥，不执行高风险操作 |

初学阶段可以先做最简单的评估：准备一批测试问题，看系统是否识别出正确意图。

## 8. 构建一个简单评估集

评估集就是提前准备好的测试样例。

每条样例通常包含：

- 输入问题
- 期望结果

下面我们先评估意图识别是否正确。

```python
eval_dataset = [
    {'input': '帮我制定 LangGraph 学习计划', 'expected_intent': 'plan'},
    {'input': '请安排一个 AI 学习路线', 'expected_intent': 'plan'},
    {'input': '解释一下什么是条件边', 'expected_intent': 'explain'},
    {'input': '什么是智能体状态', 'expected_intent': 'explain'},
    {'input': '你好，你能做什么', 'expected_intent': 'chat'},
]

print('评估集数量：', len(eval_dataset))
```

### 代码解释

这段代码定义了一个小型评估集。

#### `eval_dataset`
它是一个列表，里面每个元素都是一个测试样例。

每个样例有两个字段：

- `input`：用户输入
- `expected_intent`：期望识别出的意图

#### 为什么先评估意图
因为当前学习助手的核心流程是：

```text
输入 -> 意图识别 -> 分支处理 -> 回复
```

如果意图识别错了，后面的节点也会走错。

所以意图识别是一个很适合入门评估的指标。

## 9. 自动运行评估

有了评估集后，就可以写代码自动跑一遍，并计算准确率。

```python
def evaluate_intent(dataset):
    records = []
    correct_count = 0

    for item in dataset:
        result = run_learning_assistant(item['input'])
        predicted = result['intent']
        expected = item['expected_intent']
        is_correct = predicted == expected

        if is_correct:
            correct_count += 1

        records.append({
            'input': item['input'],
            'expected': expected,
            'predicted': predicted,
            'correct': is_correct
        })

    accuracy = correct_count / len(dataset)
    return accuracy, records

accuracy, records = evaluate_intent(eval_dataset)
print('准确率：', accuracy)
for record in records:
    print(record)
```

### 代码解释

这段代码完成了一个最小自动评估流程。

#### `evaluate_intent(dataset)`
这个函数接收评估集，然后逐条测试。

#### `result = run_learning_assistant(item['input'])`
每条测试样例都会调用一次智能体核心函数。

这和真实用户调用项目的方式是一致的。

#### `predicted` 和 `expected`
- `predicted` 是系统实际识别出的意图
- `expected` 是我们提前标注的正确意图

如果两者相等，就认为这条样例通过。

#### `accuracy`
准确率计算公式是：

```text
准确率 = 正确数量 / 总样例数量
```

#### `records`
除了给出总分，还要保存每条样例的详细结果。

因为只有总分不够。我们还需要知道到底哪些问题错了，才能继续优化。

## 10. 记录运行日志

部署后，用户的问题可能非常多。

如果没有日志，出问题时就很难排查。

日志至少应该记录：

- 用户输入
- 系统输出
- 识别出的意图
- 是否成功
- 运行时间

下面用一个简单包装函数演示如何记录日志。

```python
import time

run_logs = []

def run_with_trace(user_input):
    start_time = time.time()

    try:
        result = run_learning_assistant(user_input)
        success = True
        error = ''
    except Exception as exc:
        result = {'input': user_input, 'intent': '', 'response': ''}
        success = False
        error = str(exc)

    latency = time.time() - start_time

    log = {
        'input': user_input,
        'intent': result['intent'],
        'response': result['response'],
        'success': success,
        'error': error,
        'latency_seconds': round(latency, 4)
    }

    run_logs.append(log)
    return result

run_with_trace('解释一下什么是 LangGraph')
run_with_trace('帮我安排学习计划')

for log in run_logs:
    print(log)
```

### 代码解释

这段代码演示了最基础的追踪思路。

#### `run_logs`
这是一个列表，用来保存运行日志。

真实项目中，日志通常会写入文件、数据库或日志平台。

#### `start_time = time.time()`
记录开始时间，用来计算本次调用耗时。

#### `try ... except ...`
部署后的系统不能因为一次错误就直接崩溃。

所以这里用 `try ... except` 捕获异常，并把错误信息写入日志。

#### `latency_seconds`
表示运行耗时。

对于真实大模型应用，耗时是非常重要的指标。

用户不仅关心回答对不对，也关心等多久。

#### 追踪的价值
日志可以帮助我们回答：

- 用户都问了什么？
- 哪些问题经常失败？
- 哪类意图识别不准？
- 哪些请求耗时很长？

这些信息是后续优化智能体的重要依据。

## 11. LangSmith 是做什么的

LangSmith 是 LangChain 生态中的调试、追踪和评估平台。

你可以把它理解成智能体应用的“运行记录仪”。

它可以帮助你查看：

- 每次调用输入了什么
- 调用了哪些链、工具或模型
- 每一步输出是什么
- 哪一步出错
- 每次调用耗时多久
- token 和成本情况

本节我们不强制接入 LangSmith，因为它需要账号和环境变量配置。

但你需要理解它解决的问题：**让智能体运行过程可观察、可追踪、可评估。**

在真实项目中，如果智能体流程比较复杂，建议尽早接入类似追踪工具。

## 12. 上线前检查清单

智能体项目上线前，建议检查下面这些内容。

| 检查项 | 说明 |
| --- | --- |
| 环境变量 | API Key、Base URL 是否配置正确 |
| 依赖版本 | requirements 是否完整 |
| 基础测试 | 核心函数是否能正常运行 |
| 评估集 | 常见问题是否通过测试 |
| 错误处理 | 空输入、异常情况是否能返回友好提示 |
| 日志追踪 | 是否能记录输入、输出和错误 |
| 安全检查 | 是否避免泄露密钥和执行危险操作 |
| 成本控制 | 是否限制过长输入和频繁调用 |

这个清单不复杂，但很实用。

它能帮助你从“代码能跑”过渡到“项目能交付”。

## 13. 本节小结

本节最重要的内容有五点：

1. **部署是把智能体从个人代码变成别人可使用的服务**
2. **核心逻辑应该先封装成稳定函数，再接命令行、API 或 Web 界面**
3. **评估集可以帮助我们判断智能体是否稳定、准确**
4. **日志和追踪可以帮助我们排查问题、分析用户行为、持续优化系统**
5. **LangSmith 这类工具可以让复杂智能体流程变得可观察、可评估**

到这里，一个智能体项目就不只是能运行的 demo，而是开始具备工程化交付能力。
