# 25_项目实战二：多工具协作型智能体

## 学习目标
1. 掌握多工具协作型智能体的项目开发方法
2. 实现结合搜索引擎、计算工具和文件读取的复合型智能体
3. 学会调试和优化智能体的执行流程

本节课会完成一个小型项目：构建一个可以根据用户问题自动选择工具的智能体。它可以模拟搜索资料、执行计算、读取文件，并把结果整理成最终回答。

## 1. 什么是多工具协作型智能体

普通问答智能体主要依靠大模型自身回答问题，但大模型并不适合完成所有事情。

例如：

- 想知道最新信息，需要搜索工具
- 想做精确数学计算，需要计算工具
- 想分析本地资料，需要文件读取工具
- 想保存结果，需要写文件工具

多工具协作型智能体就像一个会安排工作的助理：它先理解用户问题，再判断该用哪个工具，最后把工具结果整理成答案。

通俗地说，它的核心流程是：

```text
用户问题 -> 判断需要什么工具 -> 调用工具 -> 整理工具结果 -> 返回答案
```

## 2. 项目需求分析

本项目要实现一个教学版多工具智能体。为了让代码容易运行，我们先不用真实搜索引擎和真实文件系统，而是用 Python 函数模拟工具。

项目需求如下：

| 需求 | 说明 |
| --- | --- |
| 搜索工具 | 根据关键词返回模拟搜索结果 |
| 计算工具 | 执行简单数学表达式 |
| 文件读取工具 | 从模拟文件中读取内容 |
| 工具选择 | 根据用户问题判断应该调用哪个工具 |
| 结果汇总 | 把工具返回结果整理为自然语言答案 |

第一版项目重点不是做得复杂，而是把“工具定义、工具选择、工具调用、结果汇总”的完整流程跑通。

## 3. 项目模块划分

我们把项目拆成 5 个模块：

1. 定义工具：准备搜索、计算、文件读取函数
2. 注册工具：把工具放入统一的工具表
3. 选择工具：根据用户问题决定用哪个工具
4. 执行工具：调用对应函数并拿到结果
5. 汇总答案：把工具执行结果整理给用户

这种拆法的好处是每个模块只负责一件事，后续调试和扩展都更方便。

## 4. 第一步：定义搜索工具

真实项目中，搜索工具可能会调用搜索引擎 API。这里为了教学简单，用一个字典模拟搜索数据库。

```python
search_database = {
    "LangChain": "LangChain 是用于开发大模型应用的框架，常用于提示词、链、工具和 RAG 应用开发。",
    "LangGraph": "LangGraph 是用于构建有状态、多步骤、可分支智能体流程的框架。",
    "RAG": "RAG 是检索增强生成技术，先检索资料，再基于资料生成答案。",
}


def search_tool(query):
    for keyword, result in search_database.items():
        if keyword.lower() in query.lower():
            return result
    return "没有找到相关搜索结果。"


print(search_tool("请介绍 LangGraph"))
```

### 代码解释

这段代码定义了一个模拟搜索工具：

1. `search_database` 是一个字典，用来模拟搜索引擎中的资料。
2. 字典的 key 是关键词，例如 `LangChain`、`LangGraph`、`RAG`。
3. 字典的 value 是搜索结果，也就是工具返回给智能体的信息。
4. `search_tool(query)` 接收用户查询内容。
5. `keyword.lower() in query.lower()` 用来做不区分大小写的关键词匹配。
6. 如果命中关键词，就返回对应搜索结果；如果没有命中，就返回“没有找到相关搜索结果”。

这个工具虽然简单，但已经体现了搜索工具的基本思想：输入查询，返回相关资料。

## 5. 第二步：定义计算工具

大模型有时会算错数，所以精确计算应该交给计算工具。

下面实现一个简单计算器，只允许安全的数学字符，避免执行危险代码。

```python
def calculator_tool(expression):
    allowed_chars = set("0123456789+-*/(). " )
    if not set(expression) <= allowed_chars:
        return "表达式中包含不支持的字符。"

    try:
        result = eval(expression)
        return f"计算结果是：{result}"
    except Exception as error:
        return f"计算失败：{error}"


print(calculator_tool("128 * 36 + 50"))
```

### 代码解释

这段代码定义了一个计算工具：

1. `calculator_tool(expression)` 接收一个数学表达式字符串。
2. `allowed_chars` 定义允许出现的字符，包括数字、加减乘除、小括号、小数点和空格。
3. `set(expression) <= allowed_chars` 用来检查表达式中的字符是否都在允许范围内。
4. `eval(expression)` 会执行数学表达式并得到结果。
5. `try...except` 用来捕获计算错误，例如表达式格式不正确。

注意：真实项目中要谨慎使用 `eval`。这里已经做了简单字符限制，但生产环境通常会使用更安全的数学表达式解析库。

## 6. 第三步：定义文件读取工具

文件读取工具适合回答和本地资料相关的问题。这里用字典模拟文件内容。

```python
fake_files = {
    "project_plan.txt": "项目计划：第一周完成需求分析，第二周完成原型开发，第三周完成测试和优化。",
    "meeting_notes.txt": "会议纪要：团队决定优先开发知识库问答功能，然后再增加多工具调用能力。",
}


def file_reader_tool(file_name):
    if file_name in fake_files:
        return fake_files[file_name]
    return "没有找到这个文件。"


print(file_reader_tool("project_plan.txt"))
```

### 代码解释

这段代码定义了一个模拟文件读取工具：

1. `fake_files` 是模拟文件系统，key 是文件名，value 是文件内容。
2. `file_reader_tool(file_name)` 接收文件名。
3. 如果文件名存在于 `fake_files` 中，就返回对应文件内容。
4. 如果文件名不存在，就返回提示信息。

真实项目中，这个工具可以改成读取本地文件、数据库记录、对象存储文件或企业文档系统。

## 7. 第四步：注册工具

如果工具越来越多，不能每次都手动写大量 if 语句。更好的方式是把工具统一注册到一个工具表中。

```python
tools = {
    "search": {
        "name": "搜索工具",
        "description": "用于查询 LangChain、LangGraph、RAG 等知识。",
        "function": search_tool,
    },
    "calculator": {
        "name": "计算工具",
        "description": "用于执行数学表达式计算。",
        "function": calculator_tool,
    },
    "file_reader": {
        "name": "文件读取工具",
        "description": "用于读取模拟文件内容。",
        "function": file_reader_tool,
    },
}

print(tools.keys())
```

### 代码解释

这段代码把所有工具放入统一的 `tools` 字典：

1. `search`、`calculator`、`file_reader` 是工具编号，后续智能体会用编号选择工具。
2. `name` 是工具的中文名称，方便展示给用户或调试时阅读。
3. `description` 是工具说明，真实智能体可以根据说明判断工具用途。
4. `function` 保存真正要调用的 Python 函数。
5. `tools.keys()` 可以查看当前注册了哪些工具。

工具注册表的好处是：新增工具时，只需要往表里加一项，不需要大幅修改主流程。

## 8. 第五步：实现工具选择器

工具选择器负责判断用户问题应该交给哪个工具。

真实项目中，工具选择可以由大模型完成。这里为了便于理解，先用关键词规则实现。

```python
def select_tool(user_input):
    if any(word in user_input for word in ["计算", "加", "减", "乘", "除", "+", "-", "*", "/"]):
        return "calculator"

    if any(word in user_input for word in ["文件", "计划", "会议", "project_plan", "meeting_notes"]):
        return "file_reader"

    return "search"


print(select_tool("帮我计算 12 * 8"))
print(select_tool("读取项目计划文件"))
print(select_tool("LangChain 是什么"))
```

### 代码解释

这段代码实现了一个规则版工具选择器：

1. `select_tool(user_input)` 接收用户输入。
2. 如果问题中包含计算相关词语或数学符号，就选择 `calculator`。
3. 如果问题中包含文件、计划、会议等词语，就选择 `file_reader`。
4. 如果前面规则都没有命中，默认选择 `search`。

这种规则方法简单直观，适合教学和小项目。但当问题复杂时，可以让大模型根据工具描述自动选择工具。

## 9. 第六步：为不同工具提取参数

选择工具之后，还需要给工具传入合适的参数。

例如计算工具需要数学表达式，文件读取工具需要文件名，搜索工具需要搜索关键词。

```python
import re


def extract_tool_input(user_input, tool_name):
    if tool_name == "calculator":
        match = re.search(r"[0-9+\-*/(). ]+", user_input)
        return match.group().strip() if match else user_input

    if tool_name == "file_reader":
        if "meeting" in user_input or "会议" in user_input:
            return "meeting_notes.txt"
        return "project_plan.txt"

    return user_input


print(extract_tool_input("帮我计算 128 * 36 + 50", "calculator"))
print(extract_tool_input("读取会议纪要", "file_reader"))
```

### 代码解释

这段代码负责从用户输入中提取工具参数：

1. `import re` 引入正则表达式模块。
2. `extract_tool_input(user_input, tool_name)` 根据工具类型提取不同参数。
3. 对计算工具，`re.search(r"[0-9+\-*/(). ]+", user_input)` 会从文本中找出数学表达式。
4. `match.group().strip()` 取出匹配结果并去掉前后空格。
5. 对文件读取工具，如果用户提到会议，就读取 `meeting_notes.txt`；否则默认读取 `project_plan.txt`。
6. 对搜索工具，直接把用户输入作为查询内容。

参数提取是工具调用中很重要的一步。工具选对了，但参数给错了，结果也会不准确。

## 10. 第七步：实现智能体主流程

现在把工具选择、参数提取、工具调用和答案汇总连接起来，形成完整智能体。

```python
def multi_tool_agent(user_input):
    tool_name = select_tool(user_input)
    tool_info = tools[tool_name]
    tool_input = extract_tool_input(user_input, tool_name)
    tool_result = tool_info["function"](tool_input)

    final_answer = f"用户问题：{user_input}\n"
    final_answer += f"选择工具：{tool_info['name']}\n"
    final_answer += f"工具输入：{tool_input}\n"
    final_answer += f"工具结果：{tool_result}"
    return final_answer


print(multi_tool_agent("帮我计算 128 * 36 + 50"))
```

### 代码解释

这段代码实现了智能体主流程：

1. `multi_tool_agent(user_input)` 是智能体入口函数。
2. `select_tool(user_input)` 判断应该使用哪个工具。
3. `tools[tool_name]` 从工具注册表中取出工具信息。
4. `extract_tool_input(user_input, tool_name)` 为工具准备输入参数。
5. `tool_info["function"](tool_input)` 调用真正的工具函数。
6. 最后把用户问题、选择的工具、工具输入和工具结果拼接成最终答案。

这就是多工具协作型智能体的最小可用版本。它的重点不是某个工具有多复杂，而是能自动完成“选工具、调工具、汇总结果”。

## 12. 加入调试日志

智能体项目经常需要调试，因为错误可能发生在工具选择、参数提取或工具执行阶段。

下面给主流程增加调试日志，方便定位问题。

```python
def debug_multi_tool_agent(user_input, verbose=True):
    if verbose:
        print(f"[调试] 用户输入：{user_input}")

    tool_name = select_tool(user_input)
    if verbose:
        print(f"[调试] 选择工具：{tool_name}")

    tool_input = extract_tool_input(user_input, tool_name)
    if verbose:
        print(f"[调试] 工具输入：{tool_input}")

    tool_result = tools[tool_name]["function"](tool_input)
    if verbose:
        print(f"[调试] 工具结果：{tool_result}")

    return f"最终回答：{tool_result}"


print(debug_multi_tool_agent("帮我计算 10 + 20 * 3"))
```

### 代码解释

这段代码增加了调试能力：

1. `verbose=True` 表示默认打印调试信息。
2. 第一条日志显示用户原始输入。
3. 第二条日志显示智能体选择了哪个工具。
4. 第三条日志显示传给工具的输入参数。
5. 第四条日志显示工具返回结果。
6. 如果不想看日志，可以调用 `debug_multi_tool_agent(question, verbose=False)`。

调试日志能帮助我们判断问题到底出在哪里：是工具没选对，还是参数没提对，还是工具本身执行失败。

## 13. 用 LangGraph 表达多工具流程

当前流程是普通 Python 函数。实际项目中，如果流程变复杂，可以用 LangGraph 把步骤拆成节点。

工作流可以设计为：

```text
START -> 选择工具 -> 执行工具 -> 汇总答案 -> END
```

```python
from typing import TypedDict


class AgentState(TypedDict):
    user_input: str
    tool_name: str
    tool_input: str
    tool_result: str
    final_answer: str


def choose_tool_node(state: AgentState):
    tool_name = select_tool(state["user_input"])
    tool_input = extract_tool_input(state["user_input"], tool_name)
    return {"tool_name": tool_name, "tool_input": tool_input}


def execute_tool_node(state: AgentState):
    tool_result = tools[state["tool_name"]]["function"](state["tool_input"])
    return {"tool_result": tool_result}


def summarize_node(state: AgentState):
    tool_label = tools[state["tool_name"]]["name"]
    final_answer = f"我使用了{tool_label}，得到结果：{state['tool_result']}"
    return {"final_answer": final_answer}
```

### 代码解释

这段代码定义了 LangGraph 版本需要的 State 和节点：

1. `AgentState` 表示工作流中流动的数据。
2. `user_input` 保存用户问题。
3. `tool_name` 保存选择出的工具编号。
4. `tool_input` 保存传给工具的参数。
5. `tool_result` 保存工具执行结果。
6. `final_answer` 保存最终回答。
7. `choose_tool_node` 负责工具选择和参数提取。
8. `execute_tool_node` 负责调用工具。
9. `summarize_node` 负责把工具结果整理成用户能看懂的回答。

用 LangGraph 后，每个步骤变成独立节点，流程更清晰，也更容易扩展。

## 14. 构建 LangGraph 工作流

如果当前环境没有安装 LangGraph，可以先运行：`%pip install langgraph`。

```python
# 如果没有安装 LangGraph，取消下一行注释后运行
# %pip install langgraph

from langgraph.graph import END, START, StateGraph


workflow = StateGraph(AgentState)

workflow.add_node("choose_tool", choose_tool_node)
workflow.add_node("execute_tool", execute_tool_node)
workflow.add_node("summarize", summarize_node)

workflow.add_edge(START, "choose_tool")
workflow.add_edge("choose_tool", "execute_tool")
workflow.add_edge("execute_tool", "summarize")
workflow.add_edge("summarize", END)

agent_app = workflow.compile()
```

### 代码解释

这段代码把节点连接成完整工作流：

1. `StateGraph(AgentState)` 创建一张流程图，并指定状态结构。
2. `add_node` 注册节点函数。
3. `START -> choose_tool` 表示从工具选择节点开始。
4. `choose_tool -> execute_tool` 表示选好工具后执行工具。
5. `execute_tool -> summarize` 表示拿到工具结果后进行汇总。
6. `summarize -> END` 表示汇总完成后结束。
7. `compile()` 把流程图编译成可运行对象。

这和前面的普通 Python 主流程做的是同一件事，只是 LangGraph 更适合管理复杂流程。

## 15. 运行 LangGraph 版智能体

现在用一个问题测试 LangGraph 版多工具智能体。

```python
initial_state = {
    "user_input": "会议纪要里说了什么？",
    "tool_name": "",
    "tool_input": "",
    "tool_result": "",
    "final_answer": "",
}

final_state = agent_app.invoke(initial_state)
print(final_state["final_answer"])
```

### 代码解释

这段代码运行 LangGraph 工作流：

1. `initial_state` 是初始状态，只有 `user_input` 有真实内容，其他字段先留空。
2. `agent_app.invoke(initial_state)` 启动工作流。
3. 工作流会依次执行工具选择、工具调用和结果汇总。
4. `final_state` 是运行结束后的完整状态。
5. `final_state["final_answer"]` 取出最终答案。

这个例子说明：当一个智能体需要多个步骤协作时，LangGraph 可以让流程更有结构。

## 16. 调试和优化建议

多工具智能体常见问题包括：

| 问题 | 可能原因 | 优化方法 |
| --- | --- | --- |
| 工具选错 | 工具描述不清或规则太简单 | 优化工具描述，增加分类规则或让模型判断 |
| 参数提错 | 用户表达复杂 | 增加参数抽取逻辑或使用结构化输出 |
| 工具报错 | 输入格式不符合要求 | 在调用前做参数校验 |
| 答案不清晰 | 只返回原始工具结果 | 增加结果解释和格式化输出 |
| 流程难排查 | 缺少中间状态 | 增加调试日志或保存执行轨迹 |

开发智能体时，不要只看最终答案，也要观察每一步的中间状态。

## 17. 小结

本节课完成了一个多工具协作型智能体项目。

你需要重点掌握：

3. 工具调用前要先选择工具，再提取参数。
4. 调试时要观察工具选择、工具输入和工具结果。
